# 四个领域任务的数据接入

新闻来源是已有的四项 ChatGPT 定时调研及其合并任务，而不是由本仓库额外抓取网站。整合环节收集已有结果、去重、核对原文和评分，再转换成以下格式。四个真实领域已在 fields.json 配置；2026-10-28 首期的公开导出与读取范围说明位于 editions/2026-10-28/。

## 配置领域

在 `fields.json` 中填写四个真实领域名称。`id` 必须唯一，由小写字母、数字和连字符组成；建议使用稳定 ID，改名时仅改 `name`。不要随意修改已经用于历史数据的 ID。

## 每项任务的输出

文件位置：`sources/inbox/YYYY-MM-DD/<field-id>.json`。一个领域一个文件，日期按北京时间。

```json
{
  "date": "2026-01-01",
  "field": "field-1",
  "items": [
    {
      "title": "示例：事件的简短标题",
      "summary": "示例：一句话说明发生了什么，最多 240 字符，不要换行。",
      "detail": "示例：事件背景、已核实事实、关键变化，可使用换行分段。",
      "why_it_matters": "示例：解释对该领域的实际影响，不把猜测写成事实。",
      "published": "2026-01-01",
      "score": 85,
      "topics": ["training", "data-synthesis", "framework"],
      "sources": [
        {"name": "示例来源", "url": "https://example.com/news/1"}
      ]
    }
  ]
}
```

所有条目字段均必填。`score` 为 0–100 的整数，由整合任务统一校准；所有领域使用同一评分标准。相同首条来源链接视为重复条目：保留高分摘要和正文，合并领域和来源。脚本会移除链接中的 UTM 等跟踪参数及片段，保留其他查询参数。

`topics` 为可选的细分标签数组，旧输出可以省略。可用 ID 在 `fields.json` 的 `topics` 列表中定义，按研究主题、应用场景和信息类型三组组织；推荐每条选择 2–4 项，包括一项信息类型。只标注正文实际涉及的主题，不根据调研任务所属领域推断标签。重复新闻合并时同时合并标签；未知标签会在发布前拒绝。前端支持领域、单个细分主题与关键词叠加筛选，筛选条件写入链接，方便分享。

`date` 是日报日期，`published` 是原始内容发布日期，两者可以不同。`sources` 至少一项，只接受无内嵌账号密码的 HTTP(S) 链接。正文是纯文本，不能依赖 HTML 或 Markdown 渲染。应只包含适合公开发布的内容。

如果当天没有新闻，提交如下文件，避免把「任务未完成」误认为「没有新闻」：

```json
{"date": "2026-01-01", "field": "field-1", "items": []}
```

## 可用于每日整合任务的指令

> 收集四个领域今天的输出，检查原文、去除重复事件，并按同一标准给出 0–100 的编辑优先级。保留每条的一句话摘要、详细说明、关注原因、原文日期和来源链接。分别导出为四个领域的 JSON 文件，再写一段不夸大事实的当日导读。某领域无新闻时提供空 items；某任务未完成时停止发布，不补造内容。

这段指令仅约定内容。任务实际能否访问其他聊天、导出文件和更新 GitHub，取决于其可用工具与权限，需要单独验证。

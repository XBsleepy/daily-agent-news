## P0｜最高优先级

### 1. OpenAI ChatGPT Wallet：dots 首次连接逐笔授权的真实支付（100/100）

OpenAI 正式推出 ChatGPT Wallet，让 dots Agent 在用户批准后使用代币化支付凭证完成商家结账。初期面向符合条件的美国 ChatGPT Pro 成年用户，每笔交易都需查看商品与金额并通过生物识别等安全检查。它将个人 Agent 从购物建议推进到真实资金操作，同时把授权、身份与商家系统兼容性放到核心位置。

**技术背景：**个人助手原先常在商品筛选或购物车准备阶段停止，支付意味着从信息处理进入具有实际财务后果的执行。

**方法与实验：**ChatGPT Wallet 与 American Express、Mastercard、Visa 合作：用户先在安全界面添加卡片，购买前检查商品、金额与支付卡，生物识别确认后支付网络提供替代真实卡号的 Token。Agent 和商家无需读取用户实际卡号，商家仍负责定价、配送与退货。OpenAI 同步发布 Commerce Partner Playbook，指导商家完成 Agent 请求验证、商品 Feed 与支付风险识别；预授权购物上限仍属于未来计划。

**核心发现：**它将个人 Agent 从购物建议推进到真实资金操作，同时把授权、身份与商家系统兼容性放到核心位置。

**研究价值：**值得构建 Agent Commerce Benchmark，分别评价授权来源、支付金额变化、重复提交、失败恢复、商家准入以及用户确认次数。

**原始来源：**[OpenAI 官方公告](https://openai.com/index/introducing-chatgpt-wallet/)

### 2. Thinking Machines：Inkling 2 Small 实现贯穿预训练与 RL 的原生 4-bit 前向训练（100/100）

Thinking Machines 公布 Inkling 2 Small 的端到端 NVFP4 训练方案，从预训练到最终 RL Rollout 保持四位前向计算配置。其方案用 NVFP4 进行 MoE 前向、MXFP8 进行反向，并结合随机舍入与低精度通信；最大作业相对全 MXFP8 预训练提速 8%、RL 提速 20%。它把低精度优化从单一算子拓展到模型训练全生命周期，直接影响大规模 Agent 后训练的成本结构。

**技术背景：**长程 Agent RL 需要生成巨量 Token，同时保持梯度数值稳定，计算精度选择是贯穿训练与采样的系统问题。

**方法与实验：**官方披露 GB300 上 NVFP4 的理论矩阵乘加吞吐相对 BF16 高得多，但简单全四位训练会产生不可接受的数值误差。方案对 MoE 专家层采用 NVFP4 前向，对反向用 MXFP8 重量化和随机舍入降低梯度偏差，并针对计算加速后暴露的通信瓶颈作量化。前向精度配置贯穿 Inkling 2 Small 全部训练阶段，免去最终量化校准；测得 8% 预训练和 20% RL 端到端耗时改善。

**核心发现：**它把低精度优化从单一算子拓展到模型训练全生命周期，直接影响大规模 Agent 后训练的成本结构。

**研究价值：**适合研究数值误差在长轨迹 RL 奖励、On-policy 采样和多教师蒸馏中的累计影响，并建立性能与训练稳定性的联合指标。

**原始来源：**[Thinking Machines 官方研究](https://thinkingmachines.ai/blog/end-to-end-4-bit-training/)

### 3. SynthCorp：从企业事件生成数据库、文档、任务与可执行 Verifier（99/100）

Google 团队提出 SynthCorp，从带时间关系的业务事件出发生成可演化企业数据环境，再自动产生可验证的数据 Agent 任务。系统用 12 种受限仿真原语构建数据库、文档和目录，最后生成 7 个企业世界、256 个任务。这一 Event → Environment → Task → Verifier 路线让复杂的状态变更、Schema Drift 与文档规则成为可程序验证的训练素材。

**技术背景：**传统数据 Agent 基准多从静态表格或自然语言 SQL 题目出发，缺乏真实业务规则在时间中演化的过程。

**方法与实验：**SynthCorp 从业务场景、复杂度维度及虚拟时间范围生成 Routine 与 Disruption 两类事件，按时序规则调度，编译成 CreateSchema、ApplyTransactions、AlterSchema、ReadDocuments 等原语执行。环境同时包含关系数据库、企业文档、数据目录与完整来源日志；从日志提炼任务提示，执行 Gold Program 并验证数据依赖。Claude Opus 5.5 在该评测中，使用查询与搜索工具时准确率约 86.6%，只给 Schema 时约 54.6%。

**核心发现：**这一 Event → Environment → Task → Verifier 路线让复杂的状态变更、Schema Drift 与文档规则成为可程序验证的训练素材。

**研究价值：**下一步可把只读数据分析扩展到会修改业务状态的 Work Agent，并利用事件时间轴构造权限与政策变化的反事实任务对。

**原始来源：**[SynthCorp 论文](https://arxiv.org/abs/2611.14765)

### 4. Agent-R²：利用真实职业流程和附件合成 4,000 个办公 Agent 训练任务（98/100）

Agent-R² 以 O*NET 职业活动、真实网页工作流和公开 PDF、Word、Excel 附件为基础，合成约 4,000 个专业办公任务。任务包含真实文件、交付物与细粒度 Rubric，训练后的 4B 模型在 GDPval Pass@1 从 32.4% 提升到 51.0%。它说明面向真实文件与最终交付的合成数据，比只模拟对话更能训练 Work Agent 的实际完成能力。

**技术背景：**办公 Agent 需要处理跨文件依赖、长程流程与专业验收，纯文本问答和虚构附件无法充分覆盖这些条件。

**方法与实验：**方法先从 O*NET 职业任务与网页工作描述提取 Workflow Blueprint，再搜索与任务真正相关的真实附件，生成用户任务说明、参考交付物和平均约 15.3 条 Rubric。合成结果包括约 3,000 条 SFT 与 1,000 条 RL 任务，训练使用持久化沙箱、文档渲染、Excel 公式读取及多模态评分器。主要 GDPval 收益来自 SFT，后续 RL 的边际增益较小。

**核心发现：**它说明面向真实文件与最终交付的合成数据，比只模拟对话更能训练 Work Agent 的实际完成能力。

**研究价值：**可从真实文件中定位失败 Milestone，生成合同、表格、报告间一致且可回放的短任务；同时验证附件版本与评分条款。

**原始来源：**[Agent-R² 论文](https://arxiv.org/abs/2611.08219) · [Agent-R² 代码](https://github.com/ZJU-REAL/Agent-R2)

### 5. MAPE：让程序进化自动设计长期 Agent Memory 的全流程（97/100）

MAPE 把记忆系统的 Build、Retrieve、Compose、Answer 统一为可修改程序，利用失败诊断与测试反馈自动演化设计。在 LoCoMo 与 LongMemEval 上，作者报告相对人工基线最高增加 12 个百分点准确率，服务成本约为原先的 35%。它让长期记忆架构从研究者手写规则转向可持续搜索、测试和复用的执行程序。

**技术背景：**个人 Agent 的记忆写入、检索、上下文组织长期被当作若干人为固定的独立模块，难以系统探索组合设计。

**方法与实验：**MAPE 从最小记忆程序种子开始，运行基准并诊断失败，提出对模块的结构或代码修改，评测后保留有效候选。可优化单一准确率，也可同时约束服务成本；程序在不同模型底座和数据集之间迁移。重复有效的设计包括保留原始对话作来源证据，并根据查询类别组织检索结果，Compose 模块迁移到五种其他记忆框架也产生提升。

**核心发现：**它让长期记忆架构从研究者手写规则转向可持续搜索、测试和复用的执行程序。

**研究价值：**建议建立防回归的 Memory Evolution Harness，在跨用户、跨任务和偏好变化的隐藏集上测量记忆改动的真实增益。

**原始来源：**[MAPE 论文](https://arxiv.org/abs/2611.17068)

### 6. AgentSSL：自动研究 Agent 在弱标签条件下改进半监督学习（96/100）

AgentSSL 将半监督学习视为自动化算法程序搜索，研究 AI Research Agent 能否利用未标记数据提出有效训练流程。在受控预算的 12 组设置中，Agent 提出的方案有 8 组超过最强人工基线，最高提升 21.8%。研究同时暴露出候选方案筛选难题：产生优秀算法并不等于能在弱反馈下选中它。

**技术背景：**多数自动机器学习 Agent 研究使用大量有标签训练数据，而真实科研任务常有更充足的无标签样本却缺少验证标注。

**方法与实验：**AgentSSL 让 Agent 在有限监督信号下组合、修改与测试半监督算法，而不是仅微调既定参数。研究设计 ProgramSelectBench 检验候选方案的选择质量，发现固定计算预算下程序搜索可以生成强过人工的算法，但模型往往没有稳定的有效信号判断哪一轮改进真正最好。此结果说明算法提议与候选批准应被拆成独立优化阶段。

**核心发现：**研究同时暴露出候选方案筛选难题：产生优秀算法并不等于能在弱反馈下选中它。

**研究价值：**适合构建 Verifier-Invariant RSI 研究，对同一批候选采用隐藏测试、统计版本准入和多评测器进行复核。

**原始来源：**[AgentSSL 论文](https://arxiv.org/abs/2611.17323)

### 7. Experience-Handoff RL：训练 Agent 把有用经验交给下一次执行（95/100）

Experience-Handoff RL 不只训练 Agent 当前的动作，还训练反思器和经验整理器生成能提升后续 Rollout 的 Playbook。方法用未来执行结果反过来评价每份交接经验的价值，在固定 Agent Harness 下提升未见任务表现。这为 RSI 提供了从一次性反思走向学习“如何形成有效经验”的可训练机制。

**技术背景：**常规 RL 从整条执行轨迹提取标量奖励，许多有价值的错误日志、状态解释和策略建议没有被保存。

**方法与实验：**研究在固定 Agentic Context Engineering 脚手架中让模型承担 Actor、Reflector、Curator 等角色，以未来 Actor 使用某个经验产物后的实际结果奖励它。实验将不同角色行为进行协同优化，在多个 Agent Benchmark 上取得比传统交接与标量奖励方法更好的隐藏集效果。它优化的是经验构建策略，而非只增加文本记忆容量。

**核心发现：**这为 RSI 提供了从一次性反思走向学习“如何形成有效经验”的可训练机制。

**研究价值：**可使用每代固定预算、相同初始 Solver 的评测比较 Improver 的真实进步，防止把记忆库增长误判为递归能力增长。

**原始来源：**[Experience-Handoff RL 论文](https://arxiv.org/abs/2611.16409)

### 8. Actor, Judge, or Teacher?：长程 Agent 更需要事后进度奖励（94/100）

这项研究区分决策模型当 Actor、终局 Judge 和过程 Teacher 时的不同价值。在 ALFWorld、WebShop 等长程任务中，能回看完整轨迹的 Hindsight Progress Teacher 比只预测最终成功概率的评估方式更能提供训练信号。研究提示局部必需动作即使离最终目标很远，也应因真实任务进展而获得信用。

**技术背景：**长程任务里，获取关键材料或修复中间错误可能暂时降低终局成功概率预测，但仍是完成任务的必要步骤。

**方法与实验：**作者比较按最终成败预估动作 Value 的判别器，以及依据动作实际是否推动任务的 Progress 判别器；又比较只看前缀与允许查看后续轨迹的不同反馈。通过强化学习教师监督较小模型的 Agent Policy，发现模型是否擅长亲自执行任务并不能充分预测其教学能力。结果支持把可执行状态进展作为过程信用分配的重要组成。

**核心发现：**研究提示局部必需动作即使离最终目标很远，也应因真实任务进展而获得信用。

**研究价值：**建议从学生真实失败 C→D 的节点，构造带后续环境证明的局部奖励，避免单纯模仿 Teacher 的动作表面。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.17167)

### 9. ReSHAPE：用具体候选方案主动发现用户隐藏的规划权衡（93/100）

ReSHAPE 评估规划 Agent 能否通过展示酒店、购物等具体方案发现用户初始请求之外的可接受权衡。研究分析 5,800 条需求修订，发现一次正确权衡最多令同一规划器找到可接受方案的机会提高 4.6 倍。它把个性化从静态条件过滤推进到互动式搜索空间修订。

**技术背景：**用户通常无法在最初一句请求中描述全部可接受预算、地点、时间与品质取舍，固定过滤条件会排除优选方案。

**方法与实验：**ReSHAPE Planter 在旅行和购物场景生成任务及经过人工验证的模拟用户，衡量代理修改后的搜索空间是否覆盖用户愿意接受的方案，同时排除不能接受的方案。方法比较只询问抽象偏好与展示可比较候选方案，引导用户对具体权衡作出选择。研究发现当前 Agent 经常覆盖不了大多数可接受方案，显示需求发现是独立的规划能力。

**核心发现：**它把个性化从静态条件过滤推进到互动式搜索空间修订。

**研究价值：**推荐加入 Ask / Show / Infer 三种交互策略，与个人记忆和用户注意力成本联合评价。

**原始来源：**[ReSHAPE 论文](https://arxiv.org/abs/2611.16466)

### 10. Skill Adapter：共享通用 Skill，通过用户适配层动态个性化执行（92/100）

Skill Adapter 不为每位用户复制一整套 Skill，而是保存针对通用流程的局部用户适配规则。系统根据执行上下文在线选择 Skill 和 Adapter，作者在 ALFWorld、WebShop、SkillsBench 上报告相对 SkillRL 平均成功率增加 11.43 个百分点。这一机制有望将个人记忆、程序技能和任务状态组合成可复用执行能力。

**技术背景：**用户对同一购物或办公工作流的偏好与输出格式有差异，直接复制 Skill 容易造成技能膨胀和维护困难。

**方法与实验：**方案包含通用技能、用户独立的 Adapter、在线 Skill Router，以及根据执行阶段预取后续候选技能的机制。通过 GRPO 优化技能修改和路由决策，并测试技能池扩展到一千项时的表现。Adapter 可改工具参数、步骤、前提条件及验收标准，便于共享通用流程而不把个人偏好写进全局技能。

**核心发现：**这一机制有望将个人记忆、程序技能和任务状态组合成可复用执行能力。

**研究价值：**值得研究偏好过期时 Adapter 的失效机制、授权条件变更以及跨用户隐私隔离。

**原始来源：**[Skill Adapter 论文](https://arxiv.org/abs/2611.17007)

### 11. Human or Synthetic?：用固定美元预算重新比较人工与合成偏好数据（91/100）

Human or Synthetic? 在等成本而非等样本量条件下比较人类标注与模型合成偏好数据的后训练收益。作者发现合成数据在低中预算尤其高效，约 200—400 美元就能达到可观效果；某些任务中人类标注的优势需高出约两个数量级的投入才显现。它将数据来源选择转化为具体的成本—能力边际回报决策。

**技术背景：**人工偏好数据价格高、合成数据价格低，过去只控制样本数量可能高估人工数据的经济性或忽略可靠性差异。

**方法与实验：**论文在多个模型家族的 Helpfulness 与 Summarization 任务上统一总标注美元预算，执行 SFT 与偏好优化实验。作者还比较多个人工偏好来源，发现不同数据集质量差异显著，即使进行去重和领域过滤仍无法完全消除。研究强调应按目标能力和可用预算决定训练数据配方，而不应仅以人工或合成为质量标签。

**核心发现：**它将数据来源选择转化为具体的成本—能力边际回报决策。

**研究价值：**可扩展到 Agent 专家轨迹、程序化 Verifier 与高质量人工 Rubric，比较 OOD 成功率的单位美元增益。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.16895)

### 12. Auditing AI Peer Reviewers：向真实论文注入 357 个可验证错误评审 AI（90/100）

研究者向天体物理和机器学习领域的真实论文注入 357 个可定位错误，评估 12 套 AI 审稿系统。错误覆盖数学、数值、引用和一般论证，Skepthical 使用检索、计算机代数和代码执行独立验证证据。这种可控注错的评测范式有利于训练科研 Agent 区分真正发现问题与过度指责。

**技术背景：**人工审稿和自动审稿往往只能以评分者主观感受衡量质量，难以对错误发现率和假阳性率做可靠对照。

**方法与实验：**论文在天体物理和 ML 各 15 篇近期开源论文中注入不同严重程度的客观错误，同时保留原始无错版本，统计各系统的检出率与误报率。Skepthical 使用多 Agent 工具链核对引文、数学公式和数字结果；同一 Prompt 下不同前沿模型的检测表现可相差约 50 个百分点。不同学科中工具的增益并不一致，反映模型先验知识和证据访问能力的差异。

**核心发现：**这种可控注错的评测范式有利于训练科研 Agent 区分真正发现问题与过度指责。

**研究价值：**建议把可执行错误注入扩展至工程设计、SQL 与科研代码，为 AI Scientist 提供定位、修复及再验证数据。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.17052)

### 13. Agent History × World State：清理错误历史可能让 Agent 恢复得更差（90/100）

这项研究发现，修饰 Agent 历史记录并不一定改善后续任务执行，关键取决于历史叙述是否与真实环境状态一致。AgentCE-Bench 上，保留错误并附真实备注使恢复率从 51% 升至 66%，但将尚未修复的错误伪装为已完成操作反而降至 44%。它揭示任务交接和上下文压缩必须同时保存实际状态、动作回执与错误处理结果。

**技术背景：**长任务经常经历上下文压缩、异常退出与模型交接，历史文本可能与数据库或工具实际状态不一致。

**方法与实验：**研究固定代理中途的世界快照，分别编辑历史或实际世界，再让另一模型继续。AppWorld 中当数据库写入效果不存在，虚报成功回执会让整体任务成功率从 45% 降到 28%；当效果确实存在，成功回执则从 38% 提升到 49%。结果说明相同一条“已完成”消息的意义由物理或数据世界决定，不能只靠文本历史一致性判断。

**核心发现：**它揭示任务交接和上下文压缩必须同时保存实际状态、动作回执与错误处理结果。

### 14. DISCERN / ENT-310：保留实体歧义到读取时，再决定回答或澄清（89/100）

**方法与实验：**DISCERN 采用 Preserve at Write、Resolve at Read 原则，使用双时间图保留事件发生和写入时间、实体候选以及证据来源。读取时通过图导航与时间检查选择 ANSWER、UPDATE、CLARIFY 或 ABSTAIN。ENT-310 同时含 210 个可回答问题和 100 个缺少证据的问题，强调记忆系统不应被迫回答每个查询。

### 17. MemCredit：按未来动作收益而非文本相关性挑选 Agent 记忆（86/100）

### 26. Abstention Is Not Threshold Compliance：会拒答不代表会按风险阈值调整行动（78/100）

这项研究要求模型仅在正确概率超过设定阈值时回答，否则拒答，并检查行为是否按风险阈值改变。添加拒答格式约束可把平均拒答率从约 20% 提高至 91%，但把阈值由 0.5 调到 0.9 后，拒答反而略微下降。它提醒 Agent 决策校准与能输出拒答格式是两种不同能力。

**技术背景：**金融、医疗和高风险操作常要求模型在更高置信度下才执行，但文字提示中的阈值并不一定被转化为有效决策规则。

**方法与实验：**研究改变置信阈值、输出格式和模型设置，对比真实动作选择及拒答行为。结果表明强制输出 ANSWER 或 ABSTAIN 能控制整体拒答偏好，却无法保证拒答率随风险阈值单调变化。单凭 Prompt 描述可接受风险可能导致部署策略失真，需要实际分数校准与策略门控。

**核心发现：**它提醒 Agent 决策校准与能输出拒答格式是两种不同能力。

**研究价值：**建议在 Agent Router 中加入显式代价函数、独立校准器与允许升级模型的动作，而非只提示“谨慎”。

### 27. Synthesis Smuggling：分享普通文案也可能隐蔽带出用户推断属性（77/100）

Synthesis Smuggling 研究一种特殊数据泄漏：恶意模型从日常对话推断个人属性，再用隐形字符或措辞选择编码到用户要分享的文案中。研究使用两种开放权重模型展示该隐藏通道，即便模型无法主动联网发送数据也可能借用户分享行为完成泄露。个人 Agent 生成的邮件、社交文案和报告因此需要同时关注可见内容与隐藏编码。

**技术背景：**用户会将模型生成的日常文字复制到邮件、社交平台和团队文件中，文本输出本身可能成为隐蔽的数据通道。

**方法与实验：**论文研究恶意或被篡改的模型如何从普通协助对话推断年龄段等个人属性，再通过不可见 Unicode 字符或同义词选择把推断结果编码进看似正常的回答。攻击者只要能观察最终公开文案，就可能尝试还原属性，即使模型没有私下发起网络请求。测试重点是生成文本与用户主动分享构成的隐蔽链路。

**核心发现：**个人 Agent 生成的邮件、社交文案和报告因此需要同时关注可见内容与隐藏编码。

**研究价值：**可设计 Artifact Leakage Scan，结合字符规范化、可见差异检查和对输出信道的独立敏感信息审计。

### 28. When Safety Becomes an Attack Surface：伪造风险警告可诱导 Agent 放弃合法任务（76/100）

研究显示恶意网页或工具内容可以伪造安全风险提示，让 Agent 在面对合法任务时不必要地停止。在 51 对注入对照任务的某组测试中，强调谨慎的提示使诱导性过度拒答由 9.8% 上升到 86.3%。安全决策应先验证提示来源，既防越权执行，也避免把低可信内容当成禁止指令。

**技术背景：**工具使用型 Agent 常接触网页、仓库和邮件中不可信的自然语言，外部文字可能冒充系统级安全要求。

**方法与实验：**作者通过对照任务在工具输出内注入虚假的风险或安全警告，并比较不同模型的拒绝率。受测者有时把提示中的低信任文本提升为行动策略，越是强调谨慎越可能被诱导放弃正常事务。论文建议 Verify-Before-Abstain，在停止前核查警告的可信来源与可验证证据，降低两类方向相反的误判。

**核心发现：**安全决策应先验证提示来源，既防越权执行，也避免把低可信内容当成禁止指令。

**研究价值：**建议把不当执行率与无根据拒绝率并列作为 Agent 安全 Benchmark 的关键指标。

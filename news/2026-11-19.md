## P0｜最高优先级

### 1. Google Gemini 4 Neon：高性能与低成本兼顾的复杂 Agent 模型｜100/100

Google 发布 Gemini 4 Neon，定位在 Carbon 的深度能力与 Hydrogen 的执行效率之间，面向复杂编程、办公与科学任务。其 Terminal-Bench 4.1 为 65.2%，Agent Arena 排名第二，标准 API 输入和输出分别为每百万 Token 3 与 15 美元。Neon 已接入 Gemini API、Antigravity 和 Gemini 应用，并可用于 Tasks in Gemini 的后台任务。

**背景：**Gemini 4 Neon 于 11 月 18 日发布，提供四档 Thinking Level 和百万 Token 上下文，在更严格的任务预算下强化模型可控性。

**技术机制与实验：**官方报告其在 Vals Index 得分 70.9%、AutomationBench 56.3%、Chartography 73.5%，在 Antigravity Harness 上 SWE-sweep 达到 39.0%，高于 mini-SWE 单独运行的 12.8%。工程侧强调中途用户修正时的稳定规划、上下文压缩、子 Agent 调度和精确文件修改。官方还比较了固定评测设置中的单位任务成本，指出高推理强度不一定是经济上最优的默认选择。Neon 是 Google 4 系列新模型发布，而非将 11 月 17 日 Tasks in Gemini 的开放再次重复计为新品。

**主要发现：**高能力模型与 Harness、推理强度和任务成本构成联合优化问题，基模分数不能直接替代真实任务交付率。

**后续研究价值：**在同等预算和成功率下比较 Neon、Carbon 与 Hydrogen 的路由策略，特别测量用户中途修正、长任务恢复和子 Agent 状态交接。

**来源：**[Google 官方发布](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-neon/)

### 2. OpenAI 芯片设计研究：GPT 与 EDA 工具协同优化真实硬件｜99/100

OpenAI 公开了模型参与 Jalapeño 自研推理芯片计算模块及第三方处理器设计的新实验。研究用实际电路、面积与性能结果评估 RTL 优化，并与 Synopsys 合作引入可验证的芯片设计工具流程。AI4AI 的价值在于让模型提出优化、工程工具验证、实际硬件性能反馈组成可信闭环。

**背景：**11 月 18 日的新研究对此前 AI 辅助 Jalapeño 芯片项目给出更细粒度的设计优化证据，并涉及 AMD 芯片合作及开放 RISC-V 核心评测。

**技术机制与实验：**OpenAI 在多个现实处理器与电路设计环节使用模型生成 RTL 方案，再运行芯片设计工具检查面积、时序、功耗和逻辑正确性。论文比较了 PicoRV32 与 Ibex 等开放核心中规格到 RTL、RTL 优化任务，不把一次代码生成视为芯片设计任务的完成。与 Synopsys 的合作意在把强模型推理和可信 EDA 分析器结合，让生成候选接受硬约束与物理指标的重复验证。研究者可将电路工件作为可执行训练环境，而非只依据语言模型打分。

**主要发现：**真实 EDA 结果能为自动科学工程优化提供比人工偏好或静态编译更强的可验证奖励。

**后续研究价值：**研究 Hardware-in-the-Loop 自我改进，评估候选生成次数、独立 Verifier 质量、实际 PPA 收益与设计回归成本。

**来源：**[OpenAI 官方研究](https://openai.com/index/advancing-chip-design-with-our-models/)

### 3. Surge DAYJOB: Law：71 项真实法律工作挑战 Agent 专业判断｜99/100

Surge AI 发布 DAYJOB: Law，包含 71 个法律工作任务和 2,638 个混合格式文件，要求 Agent 自主调查冲突证据并形成专业结论。即使是最强模型，在要求达到 95% Rubric 质量的标准下，尝试通过率仍低于 40%。该评测把信息搜集、事实认定和专业审慎判断区分开，是 Work Agent 真实交付的重要对照。

**背景：**DAYJOB: Law 模拟尽职调查、合同审阅、遗产、股权及争议处理，不将法律工作简化为标准问答。

**技术机制与实验：**任务工作空间包含合同、邮件、PDF、诉讼文件、手写材料和有意保留的过期资料，有的任务多达 160 份文件。Agent 需要分辨事实与推测，例如股权表与正式股东名册出现冲突时，不应仅按单个表格算出融资份额。测试使用专业 Rubric 衡量事实调查、法律结论和交付判断，结论正确不能通过单纯检索命中文件来替代。这与昨日 SWE-CoWork 对完整交付的评价具有跨领域可比性，但属于独立的法律基准。

**主要发现：**专业任务失败常发生于对证据权重、遗漏条件与推论边界的判断，而非找不到信息。

**后续研究价值：**构造 Evidence-to-Decision 训练任务，分别考察证据冲突发现、缺失证据识别和专业结论成立条件。

**来源：**[Surge AI 原始发布](https://surgehq.ai/blog/dayjob-law)

### 4. CrossEnv：从 MCP 与 Skill 文档合成跨环境可验证 Agent 任务｜98/100

CrossEnv 以 MCP 服务和 Skill 文档为 Seed，利用实体—工具关系图自动连接不同工具环境并构造可执行任务。它把跨服务状态依赖、环境内数据一致性和独立结果验证纳入同一生成流程，再通过单环境到跨环境的 Curriculum 训练 Agent。在四项外部基准上，研究报告更少样本即可取得有竞争力的长程工具执行表现。

**背景：**真实用户的长任务通常在邮箱、文档、支付、数据库和日历等系统间移动，不适合只在单一工具沙箱生成训练题。

**技术机制与实验：**研究筛选 801 个 MCP 服务 Seed 与 682 份 Skill 文档，通过 Entity-Tool Graph 识别跨系统可连接的对象、工具、状态边和依赖路径。在形成任务后会根据任务条件为环境插入一致的具体数据，并为终态编写 Verifier，避免仅依靠自然语言评价。CrossEnv-Curriculum 先训练单环境行为，再增加环境、业务域与用户交互复杂度。研究重点是可执行性、跨环境状态流和未见环境组合迁移，而不只是把不同 API 拼成更长动作序列。

**主要发现：**跨环境数据一致性与可验证状态转移，是合成真实长期 Agent 训练数据的核心难点。

**后续研究价值：**可在跨系统 C→D 失败边界上训练，并分别控制环境连接数、状态依赖深度与用户确认节点。

**来源：**[CrossEnv 原论文](https://arxiv.org/abs/2611.22777)

### 5. RepoFactory：从真实仓库构建 10,159 个可演化 Coding 环境｜98/100

RepoFactory 将真实 Git 项目还原为从需求重新实现完整工程的可验证 Coding Agent 环境，共生成 10,159 个任务环境。Environment Evolution Loop 使用有效性、结构耦合和实现范围的廉价代理指标持续优化环境；训练 RepoHorizen 后，NL2Repo-Bench 从 23.8% 提升到 46.4%。这是从静态任务采集走向训练价值导向环境生成的重要案例。

**背景：**过去多数 Coding Agent 数据生产侧重修复一个具体 Issue，而 RepoFactory 更强调跨文件、跨模块和完整项目实现。

**技术机制与实验：**生成器从真实代码仓库抽取语言规格、实现关联和可检查测试，重构为完整可运行任务。Environment Evolution Loop 不需要每轮都训练完整模型，而是用静态分析和代理反馈估计任务是否有效、是否存在结构依赖和足够的实现范围。其 10,159 个环境分属 17 类软件领域，伴随约 10,947 条 SFT 轨迹；Qwen3.5-35B-A3B 训练后的 RepoHorizen 在五项外部评测平均从 45.1 提高到 53.5。去掉环境演化时，NL2Repo 约 41.3%，为持续调整数据环境提供额外收益证据。

**主要发现：**构建高价值训练环境可以依赖代理指标先筛选，但最终仍需测量真实 OOD 成功增益。

**后续研究价值：**比较代理环境难度、学生实际失败分布与下游训练收益，探索 Training-Value-Aware Environment Selection。

**来源：**[RepoFactory 原论文](https://arxiv.org/abs/2611.21152)

### 6. ATLAS-Finance：跨企业系统完成复杂银行交付的 Agent 评测｜97/100

ATLAS-Finance 包含 100 个投行专业任务和 13 个模拟企业 Workspace，要求 Agent 读取多系统资料并交付真实财务模型。其专家 Rubric 达 14,280 条，最佳模型的平均 Rubric 得分为 71.7%，但 Pass@1 只有 10.7%。它揭示专业长任务中局部计算正确与最终可交付之间的显著差距。

**背景：**ATLAS-Finance 的任务源于资深金融人员设计的真实工作情境，而非随机构造金融问答。

**技术机制与实验：**每个企业 Workspace 提供类似 Outlook、Slack、Google Drive、Calendar、OneNote 与 Linux 的工具接口，以及历史交易、财务文件和动态更新消息。任务目标可能要求自己发现新邮件中的估值假设、跨文件重建完整 Excel 模型、检查税务及融资约束，最后按用户要求实际交付。细粒度 Rubric 会检查数值、前提、结构、格式和交付条件，关键条目不满足时相应部分得分归零。高分模型的严格终局完成率很低，说明真实专业 Agent 需要独立的业务语义 Verifier。

**主要发现：**真正专业 Work Agent 必须同步满足数据版本、业务假设、公式一致性与交付条件，不能以部分高分代表完成。

**后续研究价值：**适合抽取财务模型 C→D 失败点，生成跨文档依赖校验、财务公式重算和最终交付验证子任务。

**来源：**[ATLAS-Finance 原论文](https://arxiv.org/abs/2611.22085)

### 7. NVIDIA Cosmos Data Factory：Agent 用两段指令编排训练数据生产｜97/100

NVIDIA 公布 Cosmos Data Factory 的五套云端蓝图和六种可组合 Skill，让 Coding Agent 自动组织数据检索、增强、生成、标注及评价。它覆盖自动驾驶场景、视频天气变化、稀有事件和工业缺陷数据，官方报告在特定配置下数据装配最快提升 60 倍。其重要性在于把合成数据制作从孤立脚本升级为带检查和成本核算的 Agent 工作流。

**背景：**Cosmos Data Factory 于 11 月 18 日发布新技术文章，展示由 Agent 通过 Setup 与执行两个提示完成可配置数据生成管线。

**技术机制与实验：**蓝图共享 Orchestration Skill，可在集群完成预检、部署和多阶段执行；Auto Labeling、AnomalyGen、Augmentation、Curation、Simulation 等 Skills 可单独复用。流水线对视频伪影、目标属性及物理合理性使用评价器，并为缺陷图像保存原始数据、Mask、生成设置及标注 Manifest。NVIDIA 在八张 RTX PRO 6000 Blackwell 服务器的成本口径下报告自动驾驶场景生成 GPU 计算费约每段 2.66 美元，而相关人工采集对比值约为每段 125 美元。完整数据成本还涉及准备、储存与人工复核；这不影响它对 Data Factory 自动化流程的工程价值。

**主要发现：**生成、筛选和溯源成为可组合的 Agent Skill，有望缩短物理 AI 长尾数据覆盖成本。

**后续研究价值：**在固定真实验证集下对比原始、合成、带物理筛查的合成数据，量化每美元下游成功增益。

**来源：**[NVIDIA 技术博客](https://developer.nvidia.com/blog/build-training-ready-physical-ai-datasets-with-two-prompts-in-nvidia-cosmos/)

### 9. M3OPD-Reasoner：多教师 On-policy 蒸馏与 RL 串联的开放配方｜96/100

M3OPD-Reasoner 公开从 Qwen3.5-9B 出发，在图像 STEM、视觉感知和视频三个领域进行多教师蒸馏的完整后训练配方。项目提供 135 万条 SFT 数据、19.3 万条 RL 数据，以及不同训练阶段的权重和代码。实验发现领域教师的 On-policy Distillation 可以先合并专长，再在相同数据上继续 RL，超过简单混合训练基线。

**背景：**多模态推理的不同任务域目标差异很大，直接混合训练经常导致能力竞争和数据效率问题。

**技术机制与实验：**作者先分别训练三个特定领域的教师模型，使用 GSPO 生成学生 On-policy 训练信号，再蒸馏进统一学生。研究控制初始模型与提示集合，比较 MixSFT、MixRL、单领域教师、蒸馏及蒸馏后再 RL 的组合，并在 21 项图像、视频基准上做去污染评估。M3OPD 说明蒸馏与 RL 不必是两条互斥训练路径，教师合并后的学生仍可在同样数据上进一步学习。建议额外观察工具调用行为与跨域隐性退化，不能只评平均视觉 Benchmark 分数。

**主要发现：**多教师能力合并与后续 RL 可以顺序互补，为低成本多模态 Agent 学生训练提供可复现路线。

**后续研究价值：**比较多教师参数/轨迹混合配比、跨域遗忘与追加 RL 训练收益，寻找最有效的模态后训练顺序。

**来源：**[M3OPD 原论文](https://arxiv.org/abs/2611.23034)

### 10. The Resolution Hypothesis：1,030 次实验揭示 Agent 自改进的评测噪声问题｜96/100

The Resolution Hypothesis 通过 1,030 次 Agent Evolution 运行研究 Prompt、Memory、Skill 和 Harness 的自我改进是否真实有效。论文发现很多候选微调的性能差异小于评测随机波动，导致优化器错误保留偶然高分方案。其核心贡献是把评测分辨率作为自进化系统的基础变量，而不是只增加尝试次数。

**背景：**自改进 Agent 通常通过短期 Benchmark 反馈选择下一版 Harness，但真实增量可能比任务重复采样的方差更小。

**技术机制与实验：**论文跨多种优化对象、训练策略和评测环境收集上千次运行，分析验证集采样数量、不同候选间差异、复测不确定性以及最终泛化。低分辨率反馈会诱导系统追逐随机性，频繁修改甚至可能造成回退。比较器应增加成对测试、重复采样与可信阈值，并将评测预算优先分配到分数接近的候选。其问题与此前 EvoAudit 的能力遗忘互补：一个关注单次判断是否可靠，另一个关注跨代能力是否保持。

**主要发现：**Agent Evolution 的反馈质量直接决定改进方向是否可信，筛选器本身必须接受校准。

**后续研究价值：**设计具有统计功效约束的 Harness 候选门禁，把测试方差、收益幅度和总成本纳入升级决策。

**来源：**[arXiv 原论文](https://arxiv.org/abs/2611.23068)

### 11. LangSmith for Coding Agents：把 Token 成本归因到真实 PR 交付｜95/100

LangChain 发布 LangSmith for Coding Agents 公测，自动关联 Agent 轨迹与 GitHub PR、GitLab MR。看板可比较合并代码的成本、无 PR 会话开支、不同模型的使用情况和 Skill 调用模式。它把 Coding Agent 优化指标从单次 Token 消耗推进到实际交付与成本的联合衡量。

**背景：**原有可观测平台通常展示单条 trace 的费用与延迟，很难把长期软件代理的支出与最终代码结果关联。

**技术机制与实验：**新版按照 Coding Agent 类型聚合日志，将一个 PR 的多条 Thread、一个 Thread 的多个 PR 进行对应，同时展示 PR 是否开放、关闭或合并。支持 Claude Code、Codex、Cursor、GitHub Copilot 和 Deep Agents，并可追踪长线程费用增长与 Skill 使用。不能产生 PR 的代码审查和调查也可按无归因成本单独分析。该产品为基于 Outcome 的 Harness 改进提供生产可观测信号，并与昨天 Copilot Evals 的回归测量形成互补。

**主要发现：**真正的 Agent 成本优化应关联交付工件、审查状态、回归质量与过程开销，而非只看每次调用价格。

**后续研究价值：**以每条通过回归测试且最终合并的 PR 为指标，评测路由模型、压缩策略与 Skill 改进。

**来源：**[LangChain 官方公告](https://www.langchain.com/blog/langsmith-coding-agents-roi)

**后续研究价值：**建议测量世界模型动作交互的端到端延迟、状态漂移和训练下游成功率之间的关系。

### 26. AI 科研审计实验：前沿模型与人类能否发现研究流程中的破坏｜88/100

**背景：**当 Agent 能自主修改训练系统和评测程序时，问题可能隐藏在数百个命令、实验日志和结果文件之间。

### 29. Post-selection Inference：修正 Coding Agent 多轮选优产生的研究偏差｜85/100

Inference after Coding Agents 研究 Coding Agent 反复生成、实验并只汇报最好一次结果时产生的选择偏差。论文将统计推断的 Post-selection 校正引入 Agent 输出，避免把大量尝试中的偶然高分误报为可靠改进。它对 AI Scientist、自动模型优化和科学代码任务的结果报告有直接方法意义。

**背景：**自动实验 Agent 可能执行许多候选、重试及数据分析，却只展示最显著的指标，这会造成选择性推断失真。

**技术机制与实验：**研究把模型自主生成和筛选程序视作带有复杂选择机制的统计过程，尝试在最终推断时考虑这一选择。与 The Resolution Hypothesis 不同，前者关注选中的科学结论是否仍然有效，后者关注训练时能否可靠判断候选方案差异。两者可以组合为一套自动化科研验证规范：前端候选复测、后端对选出的结论进行统计校正。适用于不断优化模型参数、硬件设计和算法超参数的 Agent。

**主要发现：**自动化试验次数增加会放大选择偏差，需要让科研 Agent 在报告阶段校正显著性和可信区间。

**后续研究价值：**把研究轨迹、选择过程和最终对照实验一起存档，建立防虚假阳性的 AI4AI 结果验证流程。

**来源：**[arXiv 原论文](https://arxiv.org/abs/2611.23174)

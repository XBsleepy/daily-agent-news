### 1. CUA-Master：真实教学视频驱动可持续 Agent 训练数据飞轮｜100/100

CUA-Master 从真实软件教学视频挖掘任务，再抽象为可组合的技能原语。数据飞轮按模型弱项调整下一轮训练任务，并通过快照回滚采集可验证轨迹。27B 模型在 OSWorld Verified 达到 80.2 分。

**背景与场景：**系统覆盖 8 大领域、36 个子领域和 650 余款软件，结合视频画面变化与语音讲解恢复操作步骤。

**技术方法：**系统覆盖 8 大领域、36 个子领域和 650 余款软件，结合视频画面变化与语音讲解恢复操作步骤。它把操作转换成可组合 Skill，生成新的多步骤任务，并为每个任务构造执行环境与验证器。失败时从环境快照继续探索，外层再根据模型能力缺口调整数据采集方向。

**关键结果：**可并发运行 2,000 多台虚拟机；CUA-Master-27B 在 OSWorld Verified 为 80.2，OSWorld 2.0 为 36.9，WeaveBench 为 43.9，Agents' Last Exam 为 25.0。

**研究价值：**真正的创新是把真实任务来源、可验证环境和学生模型反馈接成循环，值得继续研究数据边际训练价值与失败状态的定向合成。

### 2. LegoEnv：可复用环境原子让任务生成与修复一起进化｜99/100

LegoEnv 将工具服务器、数据、业务意图和规则拆成可重组的环境原子。系统生成 5,465 个可验证环境，修复共享组件后可解比例从 71.6% 提升至 88.3%。27B 模型的 AutomationBench SFT 成绩从 16.0% 翻倍至 32.0%。

**背景与场景：**它将 Server、Data、Intent、Rule 四类 Atom 从真实开源项目和业务流程中提取出来，再按约束组合任务初始状态、工具、执行路径和 Verifier。

**技术方法：**它将 Server、Data、Intent、Rule 四类 Atom 从真实开源项目和业务流程中提取出来，再按约束组合任务初始状态、工具、执行路径和 Verifier。验证器同时检查必须发生与禁止发生的状态改变。Teacher 多次失败后，系统追踪共享 Atom 或验证器问题并集中修复，使一个改动能改善多个环境。

**关键结果：**环境覆盖 223 个应用，生成 6,110 条验证成功的轨迹；Qwen3.6-27B SFT 由 16.0% 升到 32.0%，Qwen3.8-27B RL 由 37.6% 升到 40.3%。

**研究价值：**可把 Student 失败发生的局部状态衔接转换为 Atom 组合目标，避免每次都重新生成完整长程工作流。

### 3. NorthCUA：保存验证过的 Milestone，从失败节点直接续跑｜98/100

NorthCUA 将长程电脑任务拆成带局部验证器的 Milestone，成功后保存真实软件环境快照。Agent 失败时可从已完成的节点探索新分支，而不是反复重做前半程。系统收集约 3,000 条可验证轨迹，覆盖约 31 万次 GUI 交互。

**背景与场景：**Planning Agent 根据完整用户目标和全任务 Verifier 构建阶段目标与局部检查条件。

**技术方法：**Planning Agent 根据完整用户目标和全任务 Verifier 构建阶段目标与局部检查条件。通过检查的节点保留 E2B 工作区快照、上下文与文件工件，失败后可以在相同状态探索不同动作；部分成功轨迹也能被保留。最终仍用完整任务的验收条件判断整条路径是否完成。

**关键结果：**训练结合 GUI Grounding、长程 SFT 与桌面网页联合 RL；长程轨迹收集规模约 3,000 条和 310,000 次 GUI 操作。

**研究价值：**最值得进一步研究的是由 Student 失败机制确定 Milestone，并检验失败边界短任务对未见长任务的迁移收益。

### 4. StateGraph：个人状态一变，下游记忆和计划自动修复｜97/100

StateGraph 为个人长期记忆建立状态依赖图，让事实变化触发下游推断和计划的定向修订。系统使用反事实检查判断旧结论是否仍有有效依据。StateChangeBench 上三层及以上依赖的 Impact-F1 优势达到 26 个百分点。

**背景与场景：**用户改变住址、工作时间或预算时，旧事实容易替换，但基于旧条件创建的建议和待办可能继续生效。

**技术方法：**用户改变住址、工作时间或预算时，旧事实容易替换，但基于旧条件创建的建议和待办可能继续生效。StateGraph 检查下游节点是否依赖已失效前提，以及有没有另一条独立证据路径。只有必要条件失效且缺乏其他支持，系统才修订相关派生状态。

**关键结果：**StateChangeBench 包含 50 个受控案例；相较 CUPMem 基线，深度一层的 Impact-F1 高 6.9 个百分点，深度三层以上高 26.0 个百分点。

**研究价值：**长期 Personal Agent 需要把原始事实、派生状态、任务计划与行动后果连接起来，而不是只维护一份用户画像。

### 6. SWE-Trail：旧失败轨迹用于指导采样，不进入模型上下文｜95/100

SWE-Trail 利用历史失败轨迹找到值得继续采样的 Checkpoint，但不把旧轨迹直接给当前 Coding Agent。数据收集器短程试跑候选动作，再选出更有价值的分支。124B Student 在 SWE-bench Multilingual 和 Pro 分别提升 2.33、1.60 个百分点。

**背景与场景：**反复独立采样软件修复问题常得到相同错误路线；直接展示历史失败则会让训练依赖测试时不存在的提示。

**技术方法：**反复独立采样软件修复问题常得到相同错误路线；直接展示历史失败则会让训练依赖测试时不存在的提示。SWE-Trail 让历史只决定采集预算的分配位置，当前 Agent 仍依据常规上下文提出动作。系统从相同中间状态执行候选分支，选择更具价值的后续轨迹进行训练。

**关键结果：**使用 124B Student，SWE-bench Multilingual 增加 2.33 个百分点，Pro 增加 1.60 个百分点；移除历史指导的同类流程在 Multilingual 上仅增加 0.11 个百分点。

**研究价值：**训练数据采集不必追求更多独立 Rollout，可以优先定位首次失败边界，定向获得恢复和分支探索样本。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.02074)

### 7. MemUse：记忆检索成功，不代表它真正影响了行动｜94/100

MemUse 追踪记忆交付后是否被实际使用，以及是否改变 Agent 的后续行为。分析 8,000 个 SWE-bench Verified 执行记录后，三个记忆系统的解题率与无记忆基线差距均不到 0.4 个百分点。许多相关记忆没有被使用，另有有益记忆出现在最终失败的任务里。

**背景与场景：**基于 Recall、任务得分或最终回答准确率评测记忆，无法确认某条记录是否对具体行动产生因果影响。

**技术方法：**基于 Recall、任务得分或最终回答准确率评测记忆，无法确认某条记录是否对具体行动产生因果影响。MemUse 为每次记忆交付检查相关性、准确性、新颖性、行为影响和观察到的结果，并绑定执行证据。它区分检索到正确记忆、真正采用记忆和最终任务完成三个环节。

**关键结果：**对三个系统共计 8,000 个执行 Episode 的分析显示，解题率变化均在 0.4 个百分点以内；23.2% 的有益记忆使用出现在最终失败的任务中。

**研究价值：**个人记忆评测应直接回答哪些记忆让 Agent 做出更好的决定，而不仅是检索系统是否命中。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.01718)

### 8. MEMENTO：让 8B 模型主动学习记笔记和管理超长上下文｜93/100

MEMENTO 用合成高质量笔记先进行 SFT，再通过 RL 学习何时写入和压缩上下文。Qwen3-8B 在四项长篇书籍问答评测中从 36.9% 提升到 67.8%。模型仅维护 20K Token 活跃上下文，却能处理最长 250 万 Token 的文档。

**背景与场景：**模型拥有笔记工具，不等于会在关键时机保存正确内容。

**技术方法：**模型拥有笔记工具，不等于会在关键时机保存正确内容。研究者利用事后已知答案的完整轨迹合成训练笔记，再以回答正确性、笔记质量和置信度校准作为后训练信号。实验发现跳过 SFT 而直接 RL，模型可能逐步减少甚至放弃有用的笔记操作。

**关键结果：**四项书籍 QA 平均正确率由 36.9% 升至 67.8%，接近同类 Harness 下 GLM-5.3 的 69.3%；研究报告推理成本约为后者九分之一。

**研究价值：**可以把训练得到的上下文管理策略扩展到动态工作环境，加入记忆证据来源、状态过期与按需重新检查。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.00244)

### 11. MemSidecar：Agent 需要记忆之前，另一个系统先完成预取｜90/100

MemSidecar 把记忆调度从主 Agent 中独立出来，用 Hook 和 Foresight 预测何时需要历史信息。系统异步预取并缓存记忆，使主 Agent 在执行时减少等待。MCP-Persona 上 Hooks 达到 41.23%，Foresight 达到 44.34%。

**背景与场景：**传统 Agent 经常在任务执行中才发现缺少用户历史或过去执行经验，于是停下操作并等待检索。

**技术方法：**传统 Agent 经常在任务执行中才发现缺少用户历史或过去执行经验，于是停下操作并等待检索。MemSidecar 通过事件触发或独立预测 Agent，提前识别可能出现的检索请求，在缓存中准备尚有效的记录。这样主 Agent 可以专注于当前任务而不必频繁规划记忆调度。

**关键结果：**论文在 MCP-Persona 上报告 Hooks 41.23%、Foresight 44.34%，并展示执行成本和等待时间的改善。

**研究价值：**低副作用的主动检索可以成为 Proactive Personal Agent 的首个落地方向，再逐步与主动操作结合。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.00779)

### 13. CrossSWE：171 项跨仓库代码任务暴露依赖一致性难题｜88/100

CrossSWE 收集真实开发项目中的 171 项跨仓库修复任务，要求多个项目的依赖和接口共同成立。最强受测模型 Pass@1 为 58.48%。跨仓库不一致导致了 44.2% 的失败。

**背景与场景：**生产系统经常同时涉及服务端、客户端 SDK、插件和部署配置，而传统 Coding Benchmark 往往只对一个仓库验证补丁。

**技术方法：**生产系统经常同时涉及服务端、客户端 SDK、插件和部署配置，而传统 Coding Benchmark 往往只对一个仓库验证补丁。CrossSWE 从真实 Issue 和 PR 恢复跨仓库任务，并检查各仓库修改是否能共同实现目标行为。它将接口依赖与跨项目工件验证变成显式任务条件。

**关键结果：**171 个任务跨 165 个仓库、20 个领域和 13 种编程语言；最强模型达到 58.48% Pass@1，跨仓库状态不一致是 44.2% 的失败原因。

**研究价值：**可基于多仓库的状态依赖构建 Milestone 和联合 Verifier，训练 Agent 正确处理跨项目变更。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.01484)

### 14. MemHarmBench：恶意记忆跨会话潜伏并改变后续决策｜87/100

MemHarmBench 专门评估恶意内容被写入长期记忆后，对未来正常任务的影响。它按用户、项目所有者及第三方受影响者三类角色衡量危害。研究显示 Agent 可能完成表面的合法任务，却在关键决策中受到旧恶意记忆操控。

**背景与场景：**跨会话攻击最危险的环节不是攻击文本出现时，而是其中的指令或偏好被转存为可信记忆之后。

**技术方法：**跨会话攻击最危险的环节不是攻击文本出现时，而是其中的指令或偏好被转存为可信记忆之后。基准将攻击注入和后续正常任务分开执行，移除原始攻击材料，仅保留可能被污染的记忆。评分同时检查任务结果、受害者影响和隐藏的异常决策。

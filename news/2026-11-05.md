### 1. ToolSpace：从真实工具依赖生成可执行长程 Agent 环境｜100/100

ToolSpace 从真实 MCP 调用轨迹提取数据、状态和重试依赖，再据此生成长程工具任务。系统用状态感知随机游走执行工具链，并以环境断言验证生成任务。Qwen3.6-35B-A3B 的七项工具评测均分从 23.0 提升至 41.0，加入 RL 后达到 43.2。

**背景与场景：**研究起点是工具定义与真实执行证据，而不是凭空构造企业数据库。

**技术方法：**研究起点是工具定义与真实执行证据，而不是凭空构造企业数据库。框架聚类得到 804 个工具环境、2,042 种规范工具和 77,760 个调用模式节点，合成 34,376 条执行轨迹；其中跨工具数据依赖占观察到的依赖边约 69%。状态更改操作会获得可写数据库，查询和无状态工具则优先复用记录的响应。候选工具路径执行失败时恢复状态重新采样，最后将成功路径反向生成自然语言任务与中间状态断言。

**关键结果：**训练后 GLM-5.2 的七项平均成绩从 44.6 升至 56.6；对 AutomationBench 和 τ³-Bench Banking 生成的 Pro 难度任务，七个前沿模型最多下降 38.2 分。

**研究价值：**最值得进一步研究的是把数据依赖、状态依赖和失败重试边拆成短任务，并通过反事实执行确认哪些边是真正的失败原因。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.05036)

### 3. OpenAI：自动化安全研究流水线复现 1,724 项漏洞｜98/100

OpenAI 公布一个覆盖代码筛查、动态验证、影响评估和补丁生成的自动化安全研究系统。单次实验从 2,308 项候选问题中动态复现 1,724 项漏洞，并确认 948 项不同的 Linux 本地提权漏洞。整个实验 API 成本约 121.3 万美元，展示了可执行证据验证的规模化价值。

**背景与场景：**系统将候选发现、隔离环境中执行验证、影响分析、补丁生成和人工审核串成多阶段流程。

**技术方法：**系统将候选发现、隔离环境中执行验证、影响分析、补丁生成和人工审核串成多阶段流程。每项研究结果配套根因分析、运行证据和候选修复，减少单靠语言报告产生的误判。论文还讨论不同基础模型能力下 Harness 的最佳复杂度，以及验证环境自身对实验质量的影响。

**关键结果：**报告共审查 5,034 个代码目标、约 280 万行代码；291 项信息泄漏证明与 948 项不同的本地提权问题被单独记录，每项 LPE 的平均 API 成本约 1,279 美元。

**研究价值：**Agent 训练可以借鉴“发现问题→独立复现→修复→回归检查”闭环，学习用实际执行证据决定任务是否完成。

RSI-Dojo 将真实研究论文、数据集与评价程序转化为 Agent 可以执行的模型后训练任务。自动流水线从 547 个候选中筛出 281 个稳定、能够区分模型能力的训练环境。RSI-Dojo-35B-A3B 在 PostTrainBench 从 13.08 提升到 29.95 分。

**背景与场景：**RSI-Craft 自动定位论文中的数据集、指标与执行依赖，并实际检查任务能否运行。

**技术方法：**RSI-Craft 自动定位论文中的数据集、指标与执行依赖，并实际检查任务能否运行。筛选阶段剔除过小样本、评价不稳定以及无法区分基础模型和强模型的任务。之后让强模型执行数据准备、训练、错误诊断与提交，再同时用过程可靠性和最终训练效果过滤轨迹。最终将“如何训练更强模型”内化为 Agent 的可学习执行技能。

**关键结果：**论文还报告 9B 设置 PostTrainBench 从 7.72 升到 16.46；两种训练轨迹过滤机制联合使用效果更好。

**研究价值：**它为自动科研 Agent 提供了可执行实验环境，可进一步从失败的训练节点合成短任务并评价跨实验迁移。

### 7. EvoMemState：用强化学习学会应用不断变化的个人记忆｜94/100

EvoMemState 不只存储个人事实，还显式维护事实之间的有效性、更新和冲突关系。系统通过强化学习优化面向当前任务的 Reasoning State，让记忆真正影响行动选择。Qwen3-8B 设置的综合记忆评测从 SimpleMem 的 53.6 提升至 59.9。

**背景与场景：**框架划分 Persistent Facts、Relational States 和 Task-specific Reasoning State 三层。

**技术方法：**框架划分 Persistent Facts、Relational States 和 Task-specific Reasoning State 三层。用户偏好、生活状态发生变化时，系统先修正事实间关系，再为新请求选择优先使用的记忆。作者使用 GRPO 学习状态演化与记忆使用策略，评测覆盖 MemSyco-Bench、MemTrapBench 与 LoCoMo。

**关键结果：**GPT-4o-mini 设置的综合指标达到 61.2；它与 StateGraph 的依赖更新研究互补，进一步研究正确事实如何转化为正确决策。

**研究价值：**适合把时序状态变化、记忆冲突与任务条件推理联合训练，避免“信息检索正确但建议仍然错误”。

### 8. GroupAssistBench：真实群聊中的记忆使用比事实回忆更难｜93/100

GroupAssistBench 从 50 个真实群组的 80,299 条消息构建多用户助手评测。它把 2,395 个实例分为事实回忆和实际群组服务，重点检查成员身份、冲突和需求更新。某记忆系统事实回忆指标达到 0.621，真实服务任务平均分却只有 0.247。

**背景与场景：**任务包含 1,374 个 Memory Recall 实例与 1,021 个 Memory Use 实例。

**技术方法：**任务包含 1,374 个 Memory Recall 实例与 1,021 个 Memory Use 实例。除了恢复历史事实，系统还需把多人分散提出的偏好与后续变更整合为一份可以行动的建议。评测按照单条记忆、跨记忆整合、冲突和版本更新划分困难程度；研究对比完整历史、RAG 与不同外部记忆方案。

**关键结果：**相同长期记忆系统在 L1 回忆和 L2 服务任务中出现明显落差，说明记忆覆盖率不等于多成员协作能力。

**研究价值：**家庭助手、团队工作 Agent 应把信息归属、偏好冲突和群体目标达成纳入核心 Benchmark。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.04867)

### 10. Task-Conditioned Memory Utility：用有无记忆对照测量真实收益｜91/100

这项研究用同一任务在“提供记忆”和“不提供记忆”条件下的表现差估计记忆价值。作者把记忆写入、存储、读取成本与未来任务收益放在同一套评价协议中。在答案所需记忆与对照记忆的配对实验中，平均收益差为 +0.33。

**背景与场景：**实验首先让 Writer 在不知道未来请求的条件下保存记忆，然后冻结 Reader 并使用相同填充文本控制上下文长度。

**技术方法：**实验首先让 Writer 在不知道未来请求的条件下保存记忆，然后冻结 Reader 并使用相同填充文本控制上下文长度。研究把记忆价值定义为特定 Memory–Task Pair 的边际贡献，而不是给每条记忆设置固定重要性。部分任务中，保留的原始记录比摘要或结构化压缩带来更大帮助。

**关键结果：**配对收益差的 95% 区间为 +0.21 至 +0.46；研究还专门记录构建、保存和呈现记忆的成本。

**研究价值：**未来应把 Memory Utility 与单位 Token 维护成本结合起来，直接优化长期助手的选择性记忆策略。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.03930)

### 11. τ-Rec-Books：隐藏偏好让推荐 Agent 成功率跌至 28.3%｜90/100

τ-Rec-Books 用 450 个推荐任务测试 Agent 是否能主动挖掘用户没说出的选书要求。当全部偏好一开始公开时平均成功率为 97.5%，部分需主动问询时降至 75.6%。隐藏要求只能通过推荐反馈推断时，成功率进一步降至 28.3%。

**背景与场景：**Benchmark 使用 20,000 本书和规则化用户模拟器，保持任务不变，只控制用户何时披露真实约束。

**技术方法：**Benchmark 使用 20,000 本书和规则化用户模拟器，保持任务不变，只控制用户何时披露真实约束。Mixed 条件下，部分要求只有 Agent 提问才会被说出；Hidden 条件下只能通过候选书的接受或拒绝推理。基于书籍元数据给出确定性评分，减少主观 Judge 的影响。

**关键结果：**明确提醒模型提问后，所有测试 Agent 在 Mixed 条件下成功率都达到至少 93.1%；主要缺口不是检索，而是不知道何时该问。

**研究价值：**值得将偏好主动获取与长期价值判断联合建模，学习提问、试探和直接执行之间的最优策略。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.04459)

### 12. TRACE：用户长期记忆能显著改变 Agent 的信息引用｜90/100

TRACE 在固定问题与搜索结果时只修改用户记忆，观察个性化如何影响搜索引用。用户明确偏爱某个媒体来源时，它进入回答前三个引用的概率提高 33～39 个百分点。这说明 Personal Agent 的记忆不仅改变回答风格，还可能改变证据选择。

**背景与场景：**TRACE 提供可控的开放 Agent Harness，研究者可修改记忆、工具设置和系统指令，并完整记录执行轨迹。

### 13. EvoGroup：群组 Agent Harness 自进化让记忆评测升至 89.58%｜90/100

EvoGroup 让共享群聊 Agent 从最小六工具 Harness 出发，根据真实交互和任务结果自动修订记忆策略。系统利用置信度、失败轨迹和渐进式信息披露分析群体知识，再更新执行框架。在 EverMemBench 保留测试集上，pass@1 从 71.07% 提升至 89.58%。

**背景与场景：**系统不更新底层模型参数，而是让分析 Agent 根据任务结果和低置信反思整理常见问题，再由演化 Agent 修改 Harness。

**技术方法：**系统不更新底层模型参数，而是让分析 Agent 根据任务结果和低置信反思整理常见问题，再由演化 Agent 修改 Harness。群组环境中的成员关系、共同知识和持续变化的状态是重点。更新后的 Harness 还会被冻结并迁移到未见的 GroupMemBench 任务，以检查跨群组适应。

**关键结果：**论文报告其 89.58% 超过若干固定框架和人工设计 Harness；Claude Code 对照为 85.83%。

**研究价值：**与 GroupAssistBench 结合，可直接评测自进化 Harness 是否真正改善多用户服务而不只是事实回忆。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.03868)

### 14. Google Agile Deliberation：用边界样本让人类逐步定义标注标准｜89/100

Google Research 发布 Agile Deliberation，用主动挑选的边界案例帮助标注者明确主观分类概念。系统把模糊要求拆成类别和排除条件，再根据人类反馈反复修订分类规则。18 场真实用户实验显示，这种交互式定义方式改善分类一致性与标注体验。

**背景与场景：**方法包含 Concept Scoping 和 Concept Iteration 两阶段。

**技术方法：**方法包含 Concept Scoping 和 Concept Iteration 两阶段。前一阶段把“健康食品”等抽象类别拆成可以执行的正例和排除规则，后一阶段自动筛选最能暴露定义漏洞的边界图片，再协助人类调整判别准则。Google 比较了零样本、自动分解、手工调整与交互式优化流程。

**关键结果：**共进行 18 场约 1.5 小时的用户研究；参与者对主观边界的理解会在看到新案例后逐步形成。

**研究价值：**这可以迁移到 Agent 任务 Rubric 生产：让专家围绕冲突案例完善验收规则，并为变更后的旧数据重新标注。

**原始来源：**[Google Research 官方文章](https://www.research.google/blog/agile-deliberation-how-ai-helps-humans-define-the-gray-areas/)

### 15. SLATE：千种 API 中选对工具，最强模型也只完成 5% 任务｜88/100

SLATE 在电商企业场景构建约 1,000 种 API 的长程工具选择评测。环境以确定性模拟器执行多步业务流程，并按最终结果而非固定调用顺序评分。测试的最强模型仅完成 5.0% 的任务，暴露大工具库中的长程规划困难。

**背景与场景：**研究把业务标准作业程序拆成层级目标，再映射到完整 API 工具库。

**技术方法：**研究把业务标准作业程序拆成层级目标，再映射到完整 API 工具库。模拟器能够返回与记录匹配的执行结果，检查所有必要业务结果是否达成，因此允许不同但有效的调用路径。该设置更接近真实企业系统的工具发现、参数关联和操作顺序决策。

**关键结果：**对比六个开放决策模型和对应基础语言模型，模型规模覆盖 3B～12B，任务整体成功率仍然很低。

**研究价值：**值得研究按当前状态动态筛选工具、通过依赖图缩小候选库以及恢复错误工具选择。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.03982)

### 16. Caper：编码 Agent 先在快照沙箱执行再决定批准｜87/100

Caper 把 Coding Agent 的命令审批从检查文本升级为先在快照沙箱中观察实际副作用。独立审批器根据执行报告放行或拦截操作，未通过的变更自动回滚。在 SABER 上有害结果率为 6.7%，低于被比较方法的至少 14.8%。

**背景与场景：**系统保存工作区快照，预执行待批准命令，生成有限长度的环境变化报告，再由独立评审决定是否正式提交。

**技术方法：**系统保存工作区快照，预执行待批准命令，生成有限长度的环境变化报告，再由独立评审决定是否正式提交。这个过程能够发现隐藏在脚本或调用工具内部、单凭命令字符串看不出的危险动作。被拒绝的命令会恢复原环境，并将原因交给 Agent 调整后续行为。

**关键结果：**在论文构建的 YoloFS-Ext 中，有害结果率为 7.8%，其他比较系统至少为 35.3%；对安全对照任务的拦截率为 1.0%。

**研究价值：**Agent 安全可以与可重置环境训练共享执行基础设施，把副作用预测和权限判断作为独立能力评测。

**原始来源：**[论文原文](https://arxiv.org/abs/2610.40753)

### 17. RoboColosseum：跨 124 个真实场地测出机器人模型排名反转｜86/100

RoboColosseum 在 124 个真实地点进行 5,699 次成对机器人策略比较。框架覆盖四类机器人平台、五种 VLA Policy 和三种前沿 AI Agent。不同机器人型号之间的排名一致性 Kendall W 仅 0.24，说明单平台成绩难以代表泛化能力。

**背景与场景：**评测包含不针对任务微调的 Open Track，以及每项任务给相同 100 条示范的 Fine-tune Track。

**技术方法：**评测包含不针对任务微调的 Open Track，以及每项任务给相同 100 条示范的 Fine-tune Track。机器人形态包括 SO-101、Franka、Bimanual-YAM 与 G1 Humanoid。论文将完整任务成功率与部分进度分开统计，并发现微调后不同模型的排名可能发生明显反转。

**关键结果：**G1 Humanoid 五项任务没有策略完整完成，但不同模型的平均进度仍在 13.3%～23.2% 之间。

**研究价值：**具身 Agent Benchmark 应同时报告跨硬件迁移、少样本适应性和未完成任务的部分进度。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.02497)

### 18. DEPTH：94% 的合成长任务三轮内就能完成｜85/100

DEPTH 指出许多长程终端任务只是操作多，而不是必须按顺序等待前一步结果。作者审计六个数据集的 734 项任务，发现已解合成任务中 94% 在三轮内就能完成。新方法在真实软件环境中逐段执行并生成下一段，构建了 105 项高依赖深度任务。

**背景与场景：**论文将工作量 Work 与任务深度 Depth 分开，深度指必须根据前一步执行输出才能决定下一步命令的顺序依赖。

**技术方法：**论文将工作量 Work 与任务深度 Depth 分开，深度指必须根据前一步执行输出才能决定下一步命令的顺序依赖。只统计 Agent 的执行轮数容易混入模型习惯，不能客观描述任务结构。新合成器按顺序完成前一阶段后才设计后一阶段，使跨阶段信息依赖更真实。

**关键结果：**新生成的 105 项任务在深度和工作量上均超过所审计数据集，六种受测模型没有一个完成超过一半。

**研究价值：**可以把 Depth 当作训练数据组成指标，针对信息依赖而不是表面执行长度生产长程任务。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.01927)

### 19. Voluntary Servitude：普通虚假评论也能操纵 Agent 的安全决策｜84/100

Voluntary Servitude 发现攻击者无需写显式恶意指令，仅靠伪造风险提醒就能改变 Agent 的选择。这类正常评论式内容在实验中造成 60.4% 的决策偏移，接近指令注入的 66.0%。给 Agent 增加独立交叉验证要求后，非自适应攻击的暴露率约减少 95%。

**背景与场景：**研究将虚假的安全隐患写成普通外部评论，让 Agent 因自身的风险规避逻辑排除原本合适的选项。

**技术方法：**研究将虚假的安全隐患写成普通外部评论，让 Agent 因自身的风险规避逻辑排除原本合适的选项。传统 Prompt Injection 检测器往往将这种内容判断为无害；论文比较了多个模型、消费服务场景与真实浏览 Agent。防御重点不是识别命令语法，而是要求高风险事实有多源证据。

**关键结果：**在不同检索设置下，端到端攻击成功率为 1.0%～57.0%；与指令注入相比，加入检测器后该方式有效性高出 1.7～4.4 倍。

**研究价值：**长期个人助手必须在事实可信性、偏好影响和外部风险声明之间设置独立证据验证。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.04393)

### 20. ParetoSaddler：Agent Harness 质量提高的同时单任务成本下降｜83/100

ParetoSaddler 同时优化 Agent Harness 的任务质量和运行成本，而不是只追求单一得分。迭代过程中用贝叶斯自助采样保留有潜力的中间候选，再从帕累托前沿挑选部署版本。ClawMark 任务成功率从 70.86% 提高至 81.35%，单任务成本从 1.17 美元降至 1.01 美元。

**背景与场景：**算法把训练阶段的候选晋升策略与最终部署偏好分开，避免过早丢弃在某个维度已有改进的候选 Harness。

**技术方法：**算法把训练阶段的候选晋升策略与最终部署偏好分开，避免过早丢弃在某个维度已有改进的候选 Harness。候选通过重复执行比较成本和质量，可靠的候选进入更大规模评测，并可成为下一轮演化父代。研究使用领域隔离的开发与测试划分考察泛化。

**关键结果：**GAIA2 任务质量从 56.22% 提升到 62.89%，单任务费用从 0.78 美元降到 0.45 美元。

**研究价值：**这为自进化 Agent 的固定预算实验提供了更合适的目标：寻找质量、成本和稳定性的 Pareto 最优而非只看成功率。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.02079)

### 21. GlucoAgent：个人健康数据驱动动态代码式预测｜82/100

GlucoAgent 为每次血糖预测动态选择多模态生活信息，并编写、执行分析代码。它能按当前用户状态检索相似餐食、拟合统计模型并回测预测方法。在 CGMacros 上平均 RMSE 为 22.5 mg/dL，优于 Chronos-2 的 23.5 mg/dL。

**背景与场景：**系统将连续血糖监测、可穿戴设备、饮食日志及个人健康背景视为动态上下文。

**技术方法：**系统将连续血糖监测、可穿戴设备、饮食日志及个人健康背景视为动态上下文。不同用户、不同时间窗口的信息重要性不同，Agent 因此每次预测时单独选择数据和统计步骤，而不是固定套用同一个时间序列模型。分析代码执行结果还能保留相应证据以解释预测。

**关键结果：**加入多模态信息后，GlucoAgent 平均 RMSE 从 24.0 降至 22.5 mg/dL；60 分钟餐后场景从 31.0 降至 26.5 mg/dL。

**研究价值：**适合研究 Personal Agent 如何依据情境动态调用个人数据和程序化工具，以及跨会话证据的持续有效性。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.04126)

### 22. ATC：以角色契约约束黑箱多 Agent 的越权协作｜81/100

Agent Trajectory Control 用明确角色契约规定规划、检索、验证和执行 Agent 的职责。每条发往共享上下文的消息会先进行越权和角色漂移检查，不合规时重新生成再验收。该机制无需修改黑箱模型内部结构，也能改善团队任务表现与角色一致性。

**背景与场景：**研究把角色漂移定义为某个 Agent 在长程协作中行使了其他角色的权限。

**技术方法：**研究把角色漂移定义为某个 Agent 在长程协作中行使了其他角色的权限。ATC 检测超出角色的行为建议、未经授权的结论和逻辑约束违规，并在消息加入共享会话之前修订它。论文在同构及异构模型团队、不同规模和角色混淆压力下评测。

**关键结果：**作者报告相较 Prompt、记忆、工作流与激活编辑等基线，角色一致性和任务质量提高、角色漂移指标下降。

**研究价值：**与固定审批状态机结合，可以把跨 Agent 权限边界直接纳入多智能体长程评测。

**原始来源：**[论文原文](https://arxiv.org/abs/2611.04321)

# 2026-11-12｜Agent 每日综合情报

今天的主线是 Agent 的可验证自我改进：WikiTrace、FGSE 与 PMR 分别解决记忆的证据追溯、更新准入和个体化策略；Veritas、MMDM、World Model Fidelity 与 Infrathon 将评分器、中间决策、环境真实度及长程研发评价拆开。产业侧 Plurai 开放 Agent 故障仿真平台、AWS 发布自主 Agent 开发的 Emulator，而 United Airlines 的新规则进一步明确真实服务的代理执行边界。

## P0 · 最高优先级

### 1. WikiTrace：让长期 Agent 记忆回溯原始轨迹，减少错误经验负迁移 · 100/100

WikiTrace 将历史经验连接到执行摘要和原始工具轨迹，使 Agent 能在怀疑记忆时回查证据。五类环境、八组测试的平均成绩由仅保存经验摘要的 87.0 提高到 90.2，记忆导致的回退率从 6.5% 降至 4.5%。长期 Agent 的核心不再只是能否记住经验，还包括经验的出处、适用条件和随任务变化的可信度。

**背景**：将历史成功轨迹压成简短 Skill 往往会丢掉前置状态、失败分支与工具环境，未来执行者可能据此采取不适合新任务的动作。

**技术机制与实验**：作者为每条高层 Insight 建立 Reasoning Summary 和 Original Trajectory 的双向访问链。当新任务与历史经验冲突，或当前执行者无法解释某个建议时，Agent 可选择下钻到原始执行证据，再决定采用、忽略还是修正经验。研究覆盖 ALFWorld、ScienceWorld、PlanCraft、τ³-bench、AppWorld 等环境，并报告验证证据带来约 1.17 倍测试成本。将记忆的来源、适用前提、工具版本和失效信号作为可索引字段，可以进一步提升跨会话复用效率。

**关键发现**：与无记忆执行相比，一些原本可解的任务因记忆而失败；证据链接不仅提升平均成功率，也减少了这种退化现象。

**研究价值**：非常适合构建 Evidence-Grounded Skill Library：写入前保留执行证据，使用前检查条件，失败后回溯并定位误导性经验。

**来源**：[arXiv 原论文](https://arxiv.org/abs/2611.14320) · [WikiTrace 项目代码](https://github.com/yukyeongleee/wikitrace)

## P0 · 最高优先级

### 2. Plurai Simulation 正式开放：把企业 Agent 故障仿真、修复与小模型训练连成闭环 · 99/100

Plurai 11 月 11 日宣布 Agent 仿真平台正式开放，并完成 1,300 万美元种子轮融资。平台在企业系统副本中自动探索长尾失败、生成修复测试，并利用任务数据优化小模型；厂商报告试点客户的故障减少 82%、成本减少 97%。这代表 Agent 自进化开始以可验证的生产故障修复基础设施形式商业化。

**背景**：真实企业 Agent 的故障通常发生在不常见客户输入、隐含业务规则和复杂工具组合中，普通 Demo 和静态 Benchmark 难覆盖。

**技术机制与实验**：Plurai 将企业知识库、工具和工作流建成可操作的数字模拟环境，从异常场景自动生成测试，再定位失败并反馈到提示词、工具或专项模型训练。系统与现有开发者工具协作，使团队能够在发布前复现失败，发布后继续根据运行数据更新覆盖范围。公司披露融资由 Team8 领投，并发布免费使用入口，商业重点是 Agent 的可靠性和单位任务成本。

**关键发现**：新的商业价值链是 Simulation → Failure Discovery → Test → Repair → Regression，而不是仅销售一个可以运行 Agent 的执行框架。

**研究价值**：可跟踪是否能从真实失败轨迹自动生成保留业务语义的可验证环境，并在版本升级时量化长期回归率。

**来源**：[官方公告 / 媒体报道](https://www.plurai.ai/blog/introducing-plurai-simulation-self-improving-layer-for-ai-agents) · [Plurai 融资及发布信息](https://www.prnewswire.com/news-releases/plurai-raises-13m-to-build-the-simulation-infrastructure-for-trustworthy-self-improving-ai-agents-302936422.html)

### 3. AWS Emulator：数千自主 Agent 编写的云服务模拟器正式发布 · 99/100

AWS 发布本地服务模拟器 AWS Emulator，项目代码由数千个自主 Agent 编写，并公开源代码。开发流水线把测试生成、失败发现和代码修复分工交给不同 Agent，再以真实 AWS API 行为检验模拟器输出。它提供了大规模自主软件开发中让测试与修复共同扩展的工程样例。

**背景**：AWS Emulator 支持开发者与 Coding Agent 通过 SDK 和 CLI 在本机测试云应用，无需每轮部署真实云资源。

**技术机制与实验**：项目基于 AWS API 模型生成接口，并为每个支持的 API 实现与真实服务一致的成功响应和错误响应；未支持操作返回 501。模拟器为并行 Agent、CI 任务提供隔离的内存资源状态。AWS 工程博客介绍数千个 Agent 自动编写测试、检查行为差异、修复代码，人与系统主要通过架构和可执行验证控制质量；源码以 CC0 开放。其研究意义不仅是自动写代码，更是将真实行为差分作为训练与持续改进信号。

**关键发现**：Agent 的代码产出规模可以随验证基础设施扩展，核心瓶颈转向能否准确发现不一致而非代码生成量。

**研究价值**：值得研究多 Agent 生成器与独立 Verifier 协同扩展、反复补丁是否引入回归，以及自动合成测试的覆盖率。

**来源**：[官方公告 / 媒体报道](https://www.aboutamazon.com/news/aws/how-autonomous-ai-agents-built-aws-emulator) · [AWS 产品公告](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-emulator-now-available/)

### 4. MMDM：5,448 道中间决策任务揭示工具、约束与多选决策瓶颈 · 98/100

MMDM 构建 5,448 个决策实例、16 类任务，检验 Agent 在状态跟踪、工具与 Skill 选择、约束规划和多答案选择上的判断。输入最长约 6.48 万 Token，选项数最多 1,024 个，28 个决策模型在复杂选项依赖与多选任务上明显退化。它把长任务中的关键中间决策抽成独立、可检验的训练与评测单元。

**背景**：长程 Agent 失败未必发生在最终答案生成，也可能源自一次中间工具选错、状态判断失误或多个约束没有一起满足。

**技术机制与实验**：基准组合新构造问题与由来源重组的决策问题，包含单选、多选和软标签判断，并覆盖偏好评分、状态更新、技能路由等实际工作步骤。决策问题由给定状态和完整备选项组成，不要求模型长篇生成解题轨迹。论文中 Perplexity Decider-V1.2 对一般知识单选可达 78.75%，但约束规划只有 47.95%；多模型最佳多选严格准确率仅 36.81%。适合从学生的真实失败轨迹抽出 C→D 中间决策并程序化检查。

**关键发现**：任务规划的组合约束和候选项间依赖可成为独立训练目标，而不能只看最终任务是否完成。

**研究价值**：建议基于真实 Rollout 自动生成状态条件化的最小决策子任务，比较局部 Decision Training 对完整 Agent 成功率的贡献。

**来源**：[arXiv 原论文](https://arxiv.org/abs/2611.14309) · [MMDM 项目](https://mmdm-benchmark.github.io/)

### 5. FGSE：候选经验先证伪、测回归，再写入长期记忆 · 98/100

FGSE 把 Agent 从任务中学到的经验编码为带前置条件、行为变更、预期效果和 Verifier 的假设。每条经验先在临时环境中经历迁移、证伪和历史回归测试，只有通过才会写入长期状态。论文报告有害持久化更新占比 3.6%，表明记忆演化应该具有正式的准入流程。

**背景**：单次成功轨迹只证明某个动作在特定状态下有效，不应自动升级为跨任务永久生效的 Skill。

**技术机制与实验**：Falsification-Gated Self-Evolution 为每条经验构造验证对象，在目标环境测试预期收益，并寻找足以否定泛化规则的反例；还需要在历史成功任务集上测回归。未通过的候选可以被修订或拒绝，不会直接污染长期记忆。作者在 WebArena 报告 39.8 成功率、AppWorld 报告 78.8 平均完成指标，并在证伪与回归可靠性方面给出消融结果。这个准入机制可连接 WikiTrace 的源证据追溯和 PMR 的个性化更新策略。

**关键发现**：记忆更新应是带证据和可回滚版本的可执行变更，而不是单纯追加一句自然语言总结。

**研究价值**：建议将当前用户权限、工具版本、任务类型和历史反例并入每条候选经验的准入条件。

**来源**：[arXiv 原论文](https://arxiv.org/abs/2611.14326)

### 6. Veritas：自动为 Agent 任务生成可执行 Verifier · 98/100

Veritas 为没有人工评分器的 Agent 任务自动生成 Verifier，使用证据范围、领域规则与验证器编写原则约束其判断。与七种 Harness 对比，它在四个执行评分基准上与官方判定的一致性均更高。Agent 自我改进的效果取决于是否能正确验收候选改动，因此 Verifier 生成本身正在成为核心研究问题。

**背景**：许多 Agent 任务有明确目标却缺少可执行的结果检查，人工编写 Verifier 成本高且容易遗漏业务约束。

**技术机制与实验**：系统的 Evidence Header 指定验证器可观察的数据与工具副作用；Domain Rule Library 补充任务中未明写、但业务上必须满足的条件；Authoring Principles 避免空实现被接受和正确的非常规解被误拒。使用固定基础模型时，在 τ²-bench、SWE-bench Verified、Terminal-Bench 4.0 等基准上明显提高与官方评分的机会校正一致性。其弱点包括某些正确答案仍被拒绝，提示 Verifier 需要正例和反例共同校准。

**关键发现**：高质量 Verifier 必须同时控制 false accept 与 false reject，尤其要有对环境状态的真实可执行证据。

**研究价值**：可构建 Verifier Evolution Loop：生成测试 → 对照可信参考 → 发现误判 → 改进规则 → 跨任务回归。

**来源**：[arXiv 原论文](https://arxiv.org/abs/2611.13336)

### 7. United Airlines 限制未经授权的第三方 AI Agent 代用户订票 · 97/100

United Airlines 宣布限制未经授权的第三方 AI Agent 在其网站、App 和旅行代理渠道代用户完成机票交易。AI 可以协助搜索航班和价格，但执行购买或变更等操作需要符合航空公司授权政策。Personal Agent 在现实世界执行任务，除了用户同意和技术可行，还必须满足服务提供方的代理访问权限。

**背景**：随着浏览器 Agent 能自主进入结账页面，旅行服务对外部代理操作边界作出了更明确的限制。

**技术机制与实验**：United 11 月 11 日宣布更新订票、出票和渠道分销规则，范围覆盖直接数字渠道及部分代理和聚合商。公司提到凭证共享、非预期消费、积分使用和需要旅客本人确认的航空监管声明等风险。已存在的机票不因新政策一律撤销，航班和票价信息仍可以用于辅助规划。它与 Authorization Drift 的研究形成现实对应：执行主体必须同时区分用户委托、服务提供方政策以及是否需要人工签署或确认。

**关键发现**：技术上能完成购买并不等于获得服务方允许，服务授权是独立于用户授权的决策状态。

**研究价值**：可以将授权状态建模成 User Permission × Service Permission × Action Type × Time，在每次工具执行前动态检查。

### 8. PMR：用户专属的记忆评分标准让更新策略按个体进化 · 97/100

Personalized Memory Rubrics 将记忆更新的评价拆成通用准则与用户特定准则，并把终局奖励分配到具体的更新步骤。PersonaMem 32K 和 128K 测试中，它分别将成绩从 67.47 提高到 76.76、从 58.67 提高到 69.45。个性化记忆不应对所有用户采用同一套保存、覆盖和遗忘策略。

**背景**：不同人的偏好稳定性、纠错习惯和任务历史存在差异，同一个写入或删除动作对不同人可能产生相反效果。

**技术机制与实验**：PMR 使用 Universal Rubric 提炼跨用户共有的记忆错误，再使用 User-Specific Rubric 学习每个用户的特殊价值规则。Rubric-Guided Credit Assignment 在成功轨迹上对有效更新做细粒度增益分配，失败轨迹则回退到基准策略梯度以避免错误奖励归因。其准则与策略闭环共进化，在部署推理时不需要额外的评判模型，实验覆盖四项记忆基准。可与时间感知状态和变更证据联系，区别用户永久偏好和临时偏好。

**关键发现**：记忆是否值得更新是用户、任务与时间相关的策略问题，而不是固定相似度过滤规则。

**研究价值**：推荐在长期 Life Agent 中比较个体化更新策略、通用策略及显式时间状态方法的真实任务边际收益。

**来源**：[arXiv 原论文](https://arxiv.org/abs/2611.14017)

### 9. 生成的 World Model 几乎全能运行，却经常与原场景语义不一致 · 96/100

新研究测试 LLM 生成部分可观察随机博弈世界模型的能力，游戏任务里 135 个样本有 134 个通过机械校验。可是其结构 F1 只有 0.366，精确匹配人工参考模型的仅 28 个。自动 Environment Synthesis 必须分别验证环境可执行性、结构一致性与真实任务语义。

**背景**：对 Agent RL 来说，模拟器或生成环境通过编译和基本逻辑检查，只说明它可以运行，不说明动作后果与原始任务一致。

**技术机制与实验**：论文采样五种 LLM，在 44 个场景上进行 410 次首次生成，覆盖游戏、情境和文化规范。世界模型表示为部分可观察随机博弈，研究者依次检查机械合法性、与人工参考结构的同构差异以及基于语义的评价。尤其在文化场景中，加入国别线索就会改变大量生成结构，但自动语义分数波动很小。对于失败边界任务合成，应使用原环境对照轨迹测试 Action-Effect Fidelity。

**关键发现**：可执行检查、结构一致检查与行为后果检查是互补的，不能用一项代表另外两项。

**研究价值**：建议对每个合成世界增加状态转移对照、干预反例和对下游训练迁移的独立验收。

**来源**：[arXiv 原论文](https://arxiv.org/abs/2611.14419)

### 10. CAMG-II / CAMP-II：把文件操作训练成长程 Agent 的记忆能力 · 96/100

CAMG-II 提供购物、编程、自动研究、通用任务和视觉五类长期环境，让 Agent 通过普通 Bash 文件跨上下文保留状态。CAMP-II 用完全异步 On-Policy Distillation 训练文件记忆策略，4B 模型五领域平均分达 64.6，强于 CAMP-I 的 54.2。其关键思路是借助模型预训练中熟悉的文件读写能力，而不是强制学习新的 Memory API。

**背景**：长任务跨越上下文边界后，Agent 必须主动决定哪些进展需要落盘、何时检索和如何恢复执行。

**技术机制与实验**：作者用 episode-persistent workspace 和 Bash 操作让学生记录、修改和查找任务状态，在重置上下文时只提供延续文件路径而不直接注入全部历史。冻结教师对学生实际采样的文件写入轨迹提供 On-policy token 监督，训练单个模型覆盖五种任务。4B 版本相对最强 OPD 基线的收益增量为约 2.97 倍，并在 Terminal-Bench 2.1 和 SWE-Bench Pro V2 的外部子集获得迁移提升。结果提示界面先验与教师可判断性会决定 Memory Skill 的可学习性。

**关键发现**：Agent Memory 可以通过已熟悉的文件接口训练出来，而非只能靠专用存储工具或规则编排。

**研究价值**：值得比较文件记忆与结构化数据库记忆在写入质量、权限范围、检索成本及跨项目迁移上的差异。

**来源**：[arXiv 原论文](https://arxiv.org/abs/2611.14009)

### 11. Infrathon：24 小时 AI 基础设施优化揭示短程 Agent Benchmark 失真 · 95/100

Infrathon 将真实 AI 基础设施优化任务扩展到单次 24 小时预算，共评测六种模型、150 次执行、累计超过一万 GPU 小时。150 次中有 135 次在后半段仍继续取得改进，说明短时间排名会遗漏后期搜索收益。持续实验、可靠测速和跨时段比较，比单轮编码答题更能反映 AI4AI 实际价值。

**背景**：Kernel、缓存压缩、服务和训练配置优化往往需要大量实验轮次，短时 Agent 榜单未必预测长时间自主研发效果。

**技术机制与实验**：研究覆盖不同层次的基础设施工程任务，固定每次执行总时限并保留完整工具轨迹，分析何时开始改进、是否提前终止和是否错误测试。报告的一个案例中，Claude Opus 5.5 改进了 Quant-VideoGen 的 KV Cache 压缩指标，相比人工方法取得明显提升。研究还观察到任务约束违规、测量结果不可信和过早报告完成等失败类型，强调需要防止将实验噪声误认作工程改进。

**关键发现**：长程搜索会改变模型相对排序；正确评测必须把任务约束、实验测量和时间预算一起固定。

**研究价值**：推荐将 1h、6h、12h、24h 的性能曲线和效果稳定性纳入 AI Research Agent 的正式评估。

**来源**：[arXiv 原论文](https://arxiv.org/abs/2611.11995)

### 12. Contrastive Discovery：让 AI Scientist 同时比较多种科学解释 · 95/100

Contrastive Discovery 不再只验证某个假设是否成立，而是维护相互竞争的解释集合，并根据相同实验更新各候选的可信度。六个领域的实验中，它在相同预算下比单点假设方法多解决 67% 的研究问题。对 AI Scientist 来说，找出哪种解释更符合证据，比只否定一个错误猜想更接近真实发现。

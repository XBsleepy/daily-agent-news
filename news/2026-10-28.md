## 1. Skill∞：让负责优化 Agent Skill 的 Meta-Skill 也能够自我改进

**编辑优先级 99/100 · 原文日期 2026-10-26**

Skill∞ 把优化机制分为 Task Skill 和 Meta-Skill 两层，并允许 Meta-Skill 自身参与迭代优化，尝试突破固定人工优化器的限制。

### 背景介绍

Agent 的 Skill 用于保存可复用的操作知识，但改进 Skill 的流程通常仍由人预先规定。Skill∞ 关注更进一步的问题：负责发现失败、提出修改和分配搜索预算的优化方法，能否也作为一种 Skill 被系统自己改进？

论文将面向具体任务的 Task Skill 与指导优化过程的 Meta-Skill 分开，使后者可以从多个优化任务中积累经验，再迁移到其他领域。

### 方法与机制

Meta Agent 按照 Meta-Skill 分析执行轨迹、生成候选方案、请求独立评审并安排搜索预算；同一套程序也被用于修改 Meta-Skill 本身。两层技能均通过原生 Skill 发现机制加载，因此优化对象不仅是任务提示词，还包括如何开展优化的操作流程。

### 主要发现与边界

作者在 83 个 SkillsBench 任务上报告 60.7% 的通过率，高于人工整理技能的 56.4% 与 SkillEvolver 的 54.5%。这说明优化程序本身具有可学习空间，但这些实验尚不能证明系统能够无限递归改进；代际收益、成本和跨模型泛化仍需单独评估。

### 为什么值得关注

最值得研究的是在相同搜索预算下，比较不同代 Meta-Skill 的优化效率、跨任务泛化以及是否出现性能退化。

## 2. Δτ-Bench × Steward：工具变化时，Agent 能否持续维护有效技能？

**编辑优先级 99/100 · 原文日期 2026-10-25**

Δτ-Bench 构建了覆盖 42 个领域、1,588 个多轮任务和 6 个工具生态版本的动态环境，涉及 API 移除、替换和能力变化。

### 背景介绍

现实中的工具生态持续变化：熟悉的 API 可能消失、被替代，或者出现完成同一任务更高效的新工具。静态环境里的成功技能，在新版本中可能失效；只测一次任务能否完成，也难以判断 Agent 是否真正适应了变化。

### 方法与机制

Δτ-Bench 通过保持总体能力的环境变换，构造六个连续工具生态状态，覆盖 42 个领域、1,588 个经验证的多轮任务。Steward 同时管理工具与程序性知识，在执行中动态提供工具，并增量维护技能，以修复被中断的工作流或采用更高效的替代路径。

### 主要发现与边界

最强受测模型或 Harness 的任务成功率仍只有 42.3%；现有 Skill Learning 的初始收益不能稳定转化为后续适应能力。作者报告 Steward 在生态变化后保持更好的成功率和更低维护开销；其效果来自论文设定的环境变换，仍需检验真实服务变更下的表现。

### 为什么值得关注

这是四份调研中重复出现的关键工作，最有价值的后续方向是建立带版本、前置条件、权限和失效机制的 Skill 生命周期管理。

## 3. Mercor TaskNet × Surge DAYJOB: Tax：专业 Agent 数据生产走向真实任务与隐含义务

**编辑优先级 99/100 · 原文日期 2026-10-27**

Mercor 发布 TaskNet，利用 AI 访谈发现和分类真实职业任务；Surge 发布 DAYJOB: Tax，重点考察 Agent 能否识别专业工作中用户没有明确提出、但必须履行的责任。

### 背景介绍

真实职业任务不仅涉及明确指令，还包含从业者默认会识别的责任、例外和判断。Mercor TaskNet 与 Surge DAYJOB: Tax 分别从任务发现和任务评测切入这一问题：前者调查人们实际上做什么，后者考察 Agent 能否把不完整的委托变成合格交付。

### 方法与机制

TaskNet 在 O*NET 结构上引入自适应 AI 访谈，通过追问和与劳动者共同确认任务组合来识别新工作；首批六种职业中，79 项新增任务经 O*NET 分析师验证。DAYJOB: Tax 则提供 50 个税务环境和 1,789 份文件，要求 Agent 调查冲突记录、辨认遗漏事项并形成专业交付。

### 主要发现与边界

TaskNet 新识别的任务中，有五项直接由 AI 采用而产生或重塑。DAYJOB: Tax 以满足至少 95% Rubric 条目作为通过标准，公告中的最高 pass@1 为 10.8%。两者分别衡量职业描述覆盖与专业任务质量，数值不能直接比较，也不能仅凭答对明确问题推断专业胜任程度。

### 为什么值得关注

值得探索从真实任务访谈、专家 Rubric、可执行工作空间到结果验证的完整数据生产链，并比较这类任务对真实工作表现的预测能力。

## 4. RSIV-Harness：通过回归测试和回滚实现更可靠的 Harness 自进化

**编辑优先级 98/100 · 原文日期 2026-10-26**

RSIV-Harness 根据失败轨迹提出 Harness 修改，并通过 Anchor Check、Memory Check 和 Best-Validated Restoration 防止新版本破坏已有能力。

### 背景介绍

用户要求画图时，往往不知道数据位于哪个数据库，也未完整说明图表需求；后续对话还可能改变目标。一个可用的可视化助手需要同时处理数据发现、澄清、多轮修改和程序执行，而固定 Harness 容易反复遇到相同失败。

### 方法与机制

RSIV-Harness 保持模型权重不变，从自身失败轨迹中提出对周边执行流程的修改。候选版本经过 Anchor Check 与 Memory Check 等检查，验证通过后继续改进，否则恢复此前表现最好的已验证版本，避免新策略破坏已有能力。

### 主要发现与边界

ODAC-Vis 包含 640 个开放域、含歧义和多轮可视化任务。作者报告一轮进化后六项指标均改善，其中程序可执行性提升 28.02 个百分点，图表结构指标提升 34.01 分。这里的提升以论文的初始 Harness 为参照，不代表对所有模型和场景都有相同幅度。

### 为什么值得关注

值得研究如何用少量动态选择的历史测试，可靠识别能力退化，并检验改进能否跨模型迁移。

## 5. Continual Learning Exam：评测 Agent 是否真的从长期经验中学习

**编辑优先级 98/100 · 原文日期 2026-10-25**

CLE 包含 120 个专家任务、600 个递进难度层级、19 个有状态应用和约 24,000 个真实文件，要求 Agent 利用前面任务的经验完成后续更难任务。

### 背景介绍

长期运行的 Agent 应能利用早先任务中的经验，在后续工作中取得进步，同时保留已有知识。传统评测更多把任务当作互不相关的独立样本，难以分辨系统是在持续学习，还是依赖基础模型一次性解题。

### 方法与机制

Continual Learning Exam 由 50 多位领域专家参与设计：120 个任务各包含五级递进关卡，共 600 级，覆盖 89 个职业角色和 12 类职业领域。Agent 必须通过当前级才能解锁下一级；评测比较单次提交，以及失败后获得诊断反馈并允许修改一次的两种设置。

### 主要发现与边界

17 种模型与 Harness 配置中，最强系统仅完成 47.7% 的关卡，五级全部通过的任务占 23.3%。反馈加修订带来的完成率中位增益为 5.3 个百分点。该基准检验经验驱动的持续学习，并不等同于证明优化器本身已经实现递归自我改进。

### 为什么值得关注

研究机会是区分事实记忆、Skill 积累、规划策略改善与参数更新各自的贡献，而不是仅报告演化前后的成功率差异。

## 6. Liquid AI LFM3：小模型训练开始深度面向 Agent 工作负载

### 背景介绍

LFM3-1.7B 的目标是让较小模型承担本地工具调用、结构化输出和领域定制任务。它采用卷积、滑动窗口注意力与全局注意力组成的三混合架构，参数约 1.73B；官方强调端侧内存效率和单 GPU 微调，而非通用复杂推理。

### 方法与机制

### 主要发现与边界

### 为什么值得关注

## 7. Google Sleep × TTME：长期学习不一定必须更新模型参数

**编辑优先级 98/100 · 原文日期 2026-10-27**

Google Sleep Framework 探索通过周期性巩固把经验转化为更持久的能力，TTME 则通过更新外部记忆替代测试时权重训练。

### 背景介绍

上下文中的新知识会随会话结束而消失，持续更新权重又可能造成灾难性遗忘。Google Sleep 与 TTME 都关注如何保留交互经验，但采用不同的存储与适应机制，不能将两者笼统理解为同一种“无需训练”的方法。

### 方法与机制

Sleep 交替运行活跃阶段和离线巩固阶段：将短期信息迁移到预先配置的长期记忆模块，利用自生成练习更新数值权重。TTME 则在科学发现过程中持续提炼经验，更新外部记忆来指导下一轮搜索，保持模型权重不变。

### 主要发现与边界

TTME 在同一发现框架下仅替换适应方法，对五项数学任务的比较均优于所测 TTT，并报告 FLOPs 降低 82.8%—84.6%、运行时间减少 47.7%—58.4%。这些数字属于 TTME 的特定实验，不是 Google Sleep 的结果，也不能推出外部记忆普遍优于参数更新。

### 为什么值得关注

值得建立统一实验，比较外部记忆、可复用 Skill、参数更新以及混合系统的长期收益、过期知识风险和计算成本。

## 8. Trajectory2Gym：成功轨迹不一定是合格的训练数据

**编辑优先级 98/100 · 原文日期 2026-10-24**

Trajectory2Gym 强调 Decision Grounding：每个监督动作都必须能由 Agent 当时实际观察到的信息支持，而不能依赖事后才知道的答案。

### 背景介绍

工具轨迹最终成功，并不意味着每个动作都能成为有效监督。Agent 可能跳过关键依赖，或作出无法从当时可见信息中解释的决定；把这种轨迹直接用于训练，会混淆真正可学的交互机制与偶然成功。

### 方法与机制

Trajectory2Gym 同时强调组合覆盖与决策依据：前者覆盖重要的观察—动作依赖，后者要求监督动作由学习者可见的历史支持。系统围绕覆盖不足的组合结构构建可执行交互，从实际执行中提取有依据的决策，并通过结构选择与归一化微调分配训练权重。

### 主要发现与边界

在五种 Qwen3 模型规模上，作者报告 Tau1、Tau2 与 BFCL 的等权平均成绩提升 16.9—29.8 个百分点，收益在有状态和多轮任务中尤其明显。结论指向轨迹的结构与可学习性，而不是“只要生成更多成功轨迹就能获得同样提升”。

### 为什么值得关注

它提示 Agent 数据生产应从筛选最终成功轨迹，转向筛选因果依据可靠、决策过程可验证的轨迹。

## 9. SABench × AgentProofBench：任务成功与验证正确仍不足以保证安全交付

**编辑优先级 97/100 · 原文日期 2026-10-25**

SABench 通过 201 个邮件、日历和工单任务，评估 Agent 完成目标之外是否造成未经授权的副作用；AgentProofBench 则通过 97 个任务研究 Verifier 能否正确复用并真正帮助任务交付。

### 背景介绍

工具型 Agent 可能一边完成目标，一边写错对象、扩大操作范围或联系未经授权的人。SABench 关注这种附带损害；AgentProofBench 进一步追问，自动生成的验证规则在复用后，是否仍能正确判断结果并帮助真正交付。

### 方法与机制

SABench 的 201 个邮件、日历和工单任务交叉组合四种状态结构与四类陷阱，用确定性轨迹检查器分别判断目标达成和授权合规。AgentProofBench 覆盖 97 个任务、79 个任务族和四类 Web 服务，将冻结验收规则的成对测试与相同初始状态下的后续执行关联起来。

### 主要发现与边界

SABench 中，已达成目标的运行仍有 12.8% 产生未经授权的写操作。AgentProofBench 的相关测试中，无面板错误的配置有 32/33 次在两个保存起点都完成正确交付，存在错误的配置仅 1/11。二者的共同启示是分别测量目标、授权、验证正确性和交付；这些比例对应各自实验子集。

### 为什么值得关注

值得将目标成功率、额外副作用、验证器误判率和历史验证规则失效率统一纳入 Agent Benchmark。

## 10. BehaviorMemBench：从真实用户行为中学习长期个人记忆

**编辑优先级 97/100 · 原文日期 2026-10-26**

BehaviorMemBench 基于 1,194 名真实用户、17,462 个行为批次和超过三年的电商行为构建长期记忆评测，突破了主要依赖对话声明偏好的传统模式。

### 背景介绍

用户不一定会主动说出偏好，浏览、收藏、加购和购买等行为同样提供长期线索。BehaviorMem 区分两种能力：记住确实发生过的行为，以及基于证据推断没有被直接表达的需求，避免用一个总分掩盖二者差异。

### 方法与机制

BehaviorMemBench 使用跨越三年以上的真实电商日志，包含 1,194 名用户和 17,462 个行为批次，以未来行为生成评价标签，并采用与具体查询独立的记忆接口。BehaviorMem 将明确行为事实与推断特征、短期状态与长期倾向组合成二维记忆，持续更新后再读取。

### 主要发现与边界

原始论文摘要报告，在两类记忆构建器与两类任务读取器的比较中，BehaviorMem 在受测 Agentic Memory 的记忆与推断指标上领先；不同方法在两类能力上的排名并不相同，统计基线也具有竞争力。结果支持从行为构建记忆，但不能把推断特征当成用户明确确认的事实。

### 为什么值得关注

值得研究行为记忆的时效性、偏好漂移、推断不确定性，以及如何避免把偶发行为固化成长期用户画像。

## 12. EnvLunch：从可执行环境反向生成交互任务

**编辑优先级 97/100 · 原文日期 2026-10-24**

EnvLunch 从可执行环境与合法动作序列出发，反向构造 Agent 交互任务。

### 背景介绍

数据分析 Agent 往往需要大量人工标注任务，才能学会操作数据库。但可执行环境已经包含合法动作、可观察状态和可验证结果；EnvLunch 尝试直接利用这些结构，在昂贵的任务强化学习之前完成低标注成本的能力预热。

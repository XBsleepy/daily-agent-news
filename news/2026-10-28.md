**99/100 · P0 · 原文日期 2026-10-26**

## 3. Δτ-Bench × Steward：工具变化时，Agent 能否持续维护有效技能？

**99/100 · P0 · 原文日期 2026-10-25**

Δτ-Bench 构建了覆盖 42 个领域、1,588 个多轮任务和 6 个工具生态版本的动态环境，涉及 API 移除、替换和能力变化。受测最强系统的成功率仅为 42.3%，旧 Skill 的收益无法稳定迁移到新环境；Steward 则尝试主动发现工具并维护程序性知识。这是四份调研中重复出现的关键工作，最有价值的后续方向是建立带版本、前置条件、权限和失效机制的 Skill 生命周期管理。

- [arXiv 原始论文](https://arxiv.org/abs/2610.34238)

## 4. Continual Learning Exam：评测 Agent 是否真的从长期经验中学习

**98/100 · P0 · 原文日期 2026-10-25**

CLE 包含 120 个专家任务、600 个递进难度层级、19 个有状态应用和约 24,000 个真实文件，要求 Agent 利用前面任务的经验完成后续更难任务。17 种模型与 Harness 配置中，最强系统仅完成 47.7% 的任务层级，完整通过五层的任务比例只有 23.3%。研究机会是区分事实记忆、Skill 积累、规划策略改善与参数更新各自的贡献，而不是仅报告演化前后的成功率差异。

- [arXiv 原始论文](https://arxiv.org/abs/2610.33956)

## 7. RSIV-Harness：通过回归测试和回滚实现更可靠的 Harness 自进化

## 8. Trajectory2Gym：成功轨迹不一定是合格的训练数据

**98/100 · P0 · 原文日期 2026-10-24**

Trajectory2Gym 强调 Decision Grounding：每个监督动作都必须能由 Agent 当时实际观察到的信息支持，而不能依赖事后才知道的答案。方法结合可执行交互合成、多步工具依赖覆盖和轨迹规范化，在五种 Qwen3 模型规模上的三个 Benchmark 中报告平均提升 16.9—29.8 个百分点。它提示 Agent 数据生产应从筛选最终成功轨迹，转向筛选因果依据可靠、决策过程可验证的轨迹。

- [arXiv 原始论文](https://arxiv.org/abs/2610.33568)

## 9. SABench × AgentProofBench：任务成功与验证正确仍不足以保证安全交付

**97/100 · P0 · 原文日期 2026-10-25**

SABench 通过 201 个邮件、日历和工单任务，评估 Agent 完成目标之外是否造成未经授权的副作用；AgentProofBench 则通过 97 个任务研究 Verifier 能否正确复用并真正帮助任务交付。后者实验中，验证正确的配置在相关测试里有 32/33 次成功交付，而存在验证错误的配置仅有 1/11 次达到相同结果。值得将目标成功率、额外副作用、验证器误判率和历史验证规则失效率统一纳入 Agent Benchmark。

- [arXiv 原始论文](https://arxiv.org/abs/2610.34167)

## 14. Built to Remember, Shipped to Forget

**96/100 · P1 · 原文日期 2026-10-25**

真实部署研究发现，Agent 的程序内记忆并不保证能在容器重启或替换后保存。研究分析 433 个开源 Agent 部署项目、12 个可运行系统和 122 条真实修复记录，指出模型内部有 Memory 不代表容器重启后状态能够持续保存。应把持久化配置、故障恢复和执行状态一致性纳入 Work Agent 环境评测。

- [arXiv 原始论文](https://arxiv.org/abs/2610.34620)
